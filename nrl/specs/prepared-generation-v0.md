# Prepared incremental generation v0

900 T12 host optimization. `Decoder::prepared_session` owns a model-bound private cache and borrows immutable checked FFN views plus reusable scratch. Its step performs the same arithmetic as the existing scalar path. KV updates append only; on failure every layer truncates to its old prefix length, the position is restored and FFN scratch is cleared. Capacity may remain allocated. This is transactional numerical state, not OS isolation or a memory-erasure guarantee. `Decoder::step` keeps its original clone-and-commit behavior for externally supplied states.

`generate_reference` preserves per-token FFN preparation. `generate_prepared` reuses preparation across a whole request, including prefill. Both retain lowest-ID argmax ties and stopping at token 1/2, at most 64 generated tokens and bounded total context. The new path checks every input token before execution.

`nrl.generation-study/0` pins exact model, tokenized prompts, generation limit and measurement counts. Before computation it limits the upper bound on all quality/warmup/timed decoder rows. `profile-generation MODEL STUDY NEW_REPORT` records alternating AB/BA timings, fresh caches, preparation included, complete generated IDs, host/executable identity and acceptance: identical IDs plus candidate p95 strictly below reference minimum. Reported generated tokens/second includes prompt prefill and early EOS; it is not isolated steady-state decode throughput. A failed timing threshold is a valid report, not a test failure. No SIMD, parallel, native, GPU, memory or compression benefit is inferred.

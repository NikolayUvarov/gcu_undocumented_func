# Mixed plans and bounded search v0

Serves 900 T09; MC-5.1, MC-8.5, MC-9.1, MC-12.1–12.3, MC-12.9. Initial interfaces: `nrl.study-profile/0`, `nrl.applied-plan/0`, `nrl.plan-selection/0`, `nrl.search/0`.

A study binds one exact unpatched decoder and one corpus, initialization/training settings, at most eight named plans with one to three distinct layers each, quality/package budgets, measurement and bounded recovery settings. Each layer has an explicit transform. Unknown/duplicate IDs, dimensions, schemas or unsupported source profiles are refused. Current transforms reduce to at most 64 source channels, then optionally apply a train-derived spline or SVD of that reduced block; no original full-width SVD claim is made.

`apply-plan TEACHER CORPUS STUDY PLAN_ID NEW_BUNDLE` independently collects original-teacher train/validation pairs, initializes from train only and fits/selects each local block. It composes all selected replacements simultaneously against the exact original teacher. Local checkpoints and their content-bound provenance accompany the standalone decoder. Local selection does not establish model-level quality. Files require new paths; the `complete.json` marker is written last. An interrupted directory without it is incomplete.

`search-plans TEACHER CORPUS STUDY NEW_BUNDLE` builds every listed plan and measures the whole candidate on validation using the shared T08 scalar backend, exact workload and measurement contract. Numerical failures remain explicit refused candidates. Dense remains a candidate. No test activation/metric fits or ranks a plan.

The decision rule is fixed in the implementation before candidate test evaluation: validation mean-NLL increase and actual package ratio must meet the supplied limits; the candidate's observed p95 time must be strictly below the dense minimum. Among eligible candidates choose lowest median, then mean NLL, then lexical plan ID. Otherwise retain dense. This nonoverlap rule describes observed samples and is not a significance test or speed guarantee. The Pareto set includes dense and considers lower validation NLL, measured median seconds and actual package bytes. Effective parameter counts and process RSS never substitute for these costs.

Only after the selection is fixed does the selected model run on test. The saved bundle contains study/corpus, every successful candidate package and validation report, local training summaries, refusals/assessments/Pareto, standalone selected model and its separate test report. Repeating search rebuilds candidates from their source and the saved fixed inputs; parameter construction is deterministic, while host times and possibly timing-dependent selection can vary. A new directory preserves each run's evidence.

The frozen example has six plans (four single-representation controls and two two-layer mixtures), eight local steps, 0.25 maximum validation NLL increase and 1.5 actual package ratio. Original dense storage is retained alongside patches, so no physical weight-memory/disk saving is claimed. Native execution, pruning source blobs, broader families, accelerator/parallel kernels and optimization of measured bottlenecks remain T11–T13.

## What it holds

- **`blockstore/src/copies.rs`** (new): the copy on the block client `init` lends in slot 4 (309-KRN-0209). It is a whole store of its own, with its own superblock, volume key (`keystore`, `volume-<id>`), index and tables.
  - A change of a copied name (`publish`, `unpublish`, `commit`) is made on the store first. Then the blocks the copy lacks are put there, and then the copy's own compare-and-swap of the name. The reply is `copied` only if all three succeed. Otherwise it is `flushed`, and the name is behind.
  - A name behind is caught up between requests. At a mount, the copy's names are compared with the store's, and a name only the copy holds is left as it is.
  - A block the store finds damaged on a read is read from the copy and put back. The scrub reads both media and repairs each from the other, then a collection frees the damaged records.
  - A memory domain's names have no copy.
- **`blockstore/src/store.rs`:**
  - `walk` is public; `domain()` and `check_block` are new.
  - **A fix of the store's mount** (`Head::keep`), found by the new random model. No version older than a kept removal is kept now. Before, a mount could bring a version back from a later commit record. There is a regression test.
- **`blockstore/src/main.rs`:** the copy mounted at start, and after a successful `recover`; the requests routed through the copies; `copy` and `copy-stat`.
- **`blockstore/linker.ld`:** a 256 KiB stack (`PT_GNU_STACK`, 262-KRN-0164). Mounting the copy beside the store overflowed 64 KiB.
- **`blockstore.wit` 2.5,** a minor version:
  - `copy(name, on)`, with the publish badge;
  - `copy-stat()`, for any client;
  - the record `copy-stats` and the error `no-copy`.

  `libmind/src/idl/blockstore.rs` is generated by `mind_idl.py`. `libmind/src/blockstore.rs` adds `Operation::Copy` and `CopyStat`.
- **`blocks`:** `copies <name> on|off` and `copy stat`.
- **Tests:**
  - `tests/blockstore_host.rs`: 11 copy tests and a random model of both media;
  - `tests/idl_fuzz_host.rs`: `copy-stats`.
  - **`tests/qemu_smoke.py`: KRN's `store_copy_disk_check` is extended** (309-KRN-0209's check, still at the start of the `store` suite). It now writes the copy and damages both disks. After the reboot it requires both disks to be found as `THE STORE'S`; it had allowed the copy's to be `BLANK`. The images are written in place (`snapshot=off`), and x86 adds `-cpu qemu64,+rdrand`.
- **Docs:** docs/storage 0.29, docs/idl, README, and the profile's Article 4 rows and evidence (x86 and aarch64). KRN's evidence row for the copy's disk now says both disks are found as the store's.
- **Nothing else changes.** `init`, `vfs_server`, `keystore` and the ABI are as before. The store's layout stays 4.

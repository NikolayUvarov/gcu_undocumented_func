# Удалённые машины для сборки и тестов через Effector

**Версия:** 1.0 (2026-10-10) · **Для кого:** все агенты и люди, работающие над MIND Core ([AGENTS.md](../AGENTS.md)) · **Конституция:** [v1.6](../constitution/RU/MIND_CORE_Constitution_v1.6.md) MC-12.1, MC-12.9 (доказательство называет свою конфигурацию) · **English version:** [effector.md](effector.md) (основной текст; русский поддерживается в соответствии с ним)

Сопровождающий даёт агентам настоящие машины для сборок и тестов через **Effector** (Эффектор) — службу, которая выполняет команды на зарегистрированных компьютерах.

- **Каждую машину делят несколько агентов.** Этот документ говорит, как работать на них, не мешая друг другу.
- **Основное описание службы** — её собственное:
  - справка для агентов, <https://hesere.uz/effector/ahelp>;
  - API, `GET https://hesere.uz/effector/api/openapi.json` (с ключом).
- **Прочитайте их первыми.** Если они расходятся с этим документом, то в том, как вызывать службу, правы они, а в том, как агенты MIND делят машины, прав этот документ.

## 2. Ключ

- **Где взять ключ.** Попросите у сопровождающего ключ API для своей сессии. Храните его только в файле в личном каталоге сессии (права 0600) и никогда в репозитории.
- **Как передавать.** Только в заголовке `X-API-Key`.
- **Где ключа быть не должно:** в URL, в командной строке (её видно в списке процессов), в журнале, коммите, задаче или ответе. Не печатайте его для проверки: `GET /api/v1/api-key` скажет, действует ли он.
- **Ключ на сессию**, чтобы сопровождающий видел, чья операция чья.

Минимальный клиент на Python (только стандартная библиотека):

```python
import json, os, time, urllib.request

BASE = "https://hesere.uz/effector"
KEY = open(os.environ["EFFECTOR_KEY_FILE"]).read().strip()  # файл 0600 в вашем личном каталоге

def call(method, path, body=None):
    data = json.dumps(body).encode() if body is not None else None
    request = urllib.request.Request(BASE + path, data=data, method=method,
                                     headers={"X-API-Key": KEY, "Content-Type": "application/json"})
    with urllib.request.urlopen(request, timeout=60) as reply:
        return json.load(reply)
```

## 3. Постановка работы

Операция выполняет один скрипт оболочки на машине от имени пользователя:

```python
script = open("build_and_test.sh").read()   # POSIX sh; вывод короткий (хвосты журналов)
op = call("POST", "/api/v1/operations", {
    "agent_id": "PCU_585240b00e8a", "kind": "exec", "run_as": "un", "command": script,
    "timeout_seconds": 3600,             # предел выполнения: не больше 3600
    "sequential": True,                  # долгая или тяжёлая работа ждёт в очереди машины
    "queue_ttl_seconds": 6 * 3600,       # сколько она может ждать за работой других агентов
    "idempotency_key": "KRN-351-KRN-0057-x86-20261010T0400",
    "reason": "KRN 351-KRN-0057: the x86 group on QEMU 8.2.2"})
FINAL = {"completed", "failed", "timeout", "expired", "cancelled", "rollback",
         "run_as_unavailable", "interactive_session_unavailable", "denied"}
while op["status"] not in FINAL:
    time.sleep(5)
    op = call("GET", f"/api/v1/operations?id={op['id']}")
    # пока ждёт: op["queue_position"], 1 — следующая
print(op["status"], op.get("result", {}).get("exit_code"), op.get("result", {}).get("stdout", "")[-3000:])
```

### Правила совместной работы

1. **Долгая или тяжёлая работа ставится в очередь.** Это сборка, тесты на хосте, набор QEMU или группа гейта: укажите `"sequential": true`.
   - Все такие операции одной машины, от какого бы агента они ни пришли, ждут в одной очереди «первым пришёл — первым выполнен» и идут по одной.
   - `queue_ttl_seconds` выбирайте по той очереди, которую видите (`GET /api/v1/operations?agent_id=…&status=active`). Ожидание входит в этот срок, и операция, прождавшая дольше, истекает.
   - Короткие проверки только на чтение (версии, свободное место, хвост журнала) ставятся без очереди и идут рядом с ней.
2. **Ничто не переживает свою операцию.** Никаких `nohup`, `&`, `setsid`, `screen`, `tmux` или `systemd-run` для работы. Отсоединённая работа идёт мимо очереди и сталкивается со сборкой или тестом следующего агента.
3. **Одна операция идёт не больше часа** (`timeout_seconds` ≤ 3600). Длинную работу делите на операции, каждая из которых укладывается, и ставьте их в очередь друг за другом: например, по одной группе QEMU или одной сборке.
4. **У каждого трека свой каталог:** `/home/un/mind-core/<TRK>/` (например `/home/un/mind-core/NET/`), со своим клоном и своими каталогами `target/`.
   - Никогда не собирайте в чужом каталоге, не чистите и не меняйте его.
   - Клон трека ядра пока лежит в `/home/un/mind-core/gcu_undocumented_func` и переезжает в `KRN/`.
   - Тестовые скрипты пишут в постоянные пути под `/tmp` (`/tmp/mind-core-*`, `/tmp/mind-*-target`). Это ещё одна причина, по которой сборки и прогоны QEMU должны идти через очередь, даже из разных каталогов.
5. **Называйте свои операции.**
   - `idempotency_key` начинается с кода вашего трека и уникален для каждой новой постановки.
   - `reason` называет трек, задачу и что выполняется (`"STO 300-STO-0002: the store suite on x86"`). Сопровождающий читает его на панели.
6. **Повтор без дублей.**
   - Оборвавшийся вызов мог успеть поставить операцию. Прежде чем ставить снова, посмотрите активные операции и, если ваша там, дождитесь её.
   - Повторяя постановку, в которой не уверены, используйте тот же `idempotency_key`.
7. **Отменяйте только свою операцию, по её ID** (`POST /api/v1/operations/cancel` с `operation_id`). Никогда не отменяйте по `agent_id`: так отменится ожидающая работа всех агентов на машине.
8. **Работайте от `un`.**
   - Учётная запись root (`run_as` `service`) — только для изменения машины, о котором попросил сопровождающий. Запишите такое изменение в раздел 6 в том же коммите, что и работу, которой оно понадобилось.
   - Не ставьте, не удаляйте и не обновляйте пакеты, не меняйте `/opt`, `/usr/local` и настройки системы для своего удобства. Спросите сопровождающего.
9. **Никогда не перезагружайте и не выключайте машину** и никогда не трогайте:
   - её сетевые настройки;
   - её пользователей, `ssh` и службу, которая запускает агента Effector;
   - другие её службы и файлы других пользователей.

   Машина без сети недоступна, пока кто-нибудь не подойдёт к ней.
10. **`fast-test` и здесь никогда не собирается и не тестируется** ([AGENTS.md](../AGENTS.md), раздел 4): только своя ветка.
11. **Убирайте за собой.** Удаляйте свои большие результаты, когда они не нужны. Перед большой сборкой посмотрите `df -h /home`.

## 4. Гейты на удалённой машине

- **Гейт через Effector — это локальный гейт** в смысле [AGENTS.md](../AGENTS.md), раздел 4, если прошли все группы `scripts/ci_local.sh`.
- **Указывайте, где он шёл:** «локальный гейт на PCU через Effector», и называйте конфигурацию из раздела 1.
- **Пока полный гейт там не помещается** (раздел 1), удалённая машина добавляет доказательства рядом с гейтом и не заменяет его.

## 5. Если что-то пошло не так

- **`timeout` с «agent did not acknowledge»** не доказывает, что ничего не выполнилось. Посмотрите результат операции и состояние машины, прежде чем повторять.
- **Ошибки HTTP несут `X-Effector-Request-ID`.** Сохраните его, когда сообщаете о проблеме сопровождающему.
- **Машина не отвечает:** скажите сопровождающему. Не пытайтесь восстановить её сами.

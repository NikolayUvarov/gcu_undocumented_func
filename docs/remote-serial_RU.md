# Последовательные порты через Effector: консоль по RS-232 и RS-485 и MIND Link до MIND Core

**Версия:** 0.1 (2026-11-08), предложение · **Запросил:** мейнтейнер, 2026-11-08 · **Написала:** сессия ядра (`KRN`, `PRT`) · **Владельцы частей:** `EFF` (раздел 4: передаёт его проекту Effector; раздел 5.2), `LNK` (раздел 5.1), сессия ядра (раздел 5.3) · **Конституция:** MC-7.1, MC-7.4, MC-7.5, MC-7.6, MC-12.1, MC-12.3, MC-12.4 · **Английская версия:** [remote-serial.md](remote-serial.md) (эталон; версии держатся в согласии)

**Ничего из описанного здесь ещё нет.** Страница говорит, что строить и кому (MC-12.3). Владелец каждой части превращает её в задачи и может менять устройство. Изменение того, что здесь названо решённым, возвращается к мейнтейнеру.

## 1. Зачем

- **У PinePhone ([100000](../issues/100000-a-phone-the-pinephone-first.md)) одна линия наружу:** UART0 через гнездо наушников, 3,3 В, 115200 8N1.
  - Сети у телефона нет, пока не заработает его Wi-Fi (этап 3).
  - Собственному агенту Effector внутри MIND Core (`effector`, главная задача [750](../issues/750-effector-agent.md)) нужна сеть, так что до тех пор он телефон не обслужит.
  - А первому пробному запуску уже нужно обновлять систему, собирать её журналы и проводить тесты.
- **`effector485` делает всё это по кабелю** ([docs/link/effector485_RU.md](link/effector485_RU.md)), но только локально, намеренно (мейнтейнер, 2026-10-30). Сессия с другой машины просит `LNK` выполнить её работу.
- **Запрос мейнтейнера (2026-11-08):**
  - модуль удалённого управления, чтобы через Effector транслировать консоль и по RS-232, и по RS-485;
  - агент Effector на хосте Linux или Windows связывается с MIND Core через link;
  - `EFF` объясняет проекту Effector, что там построить, и передаёт ему.
- **Не только для MIND Core.** Простая консоль через Effector нужна и для:
  - собственной прошивки телефона (Tow-Boot, U-Boot), которая печатает до старта MIND Core;
  - строк нашего загрузчика;
  - любой другой платы с последовательной консолью.

## 2. Схема

```
 сессия агента, где угодно
        │  HTTPS, ключ сессии
        ▼
 сервер Effector (hesere.uz/effector)
        │  собственный канал и токен агента хоста
        ▼
 агент Effector на хосте Linux или Windows ──── политика его владельца (раздел 4.1)
        │ модуль последовательных портов
        ├── режим "console": байты как есть ── /dev/ttyUSB0, TTL 3,3 В ── UART0 PinePhone
        │                                        (Tow-Boot, загрузчик, ядро, потом оболочка)
        └── режим "link": ведущий MIND Link, через effector485 (раздел 4.4)
                         └── COM22, пара RS-485 ── машины MIND Core по адресам 1, 2, 3: `link`
```

- **Хост** — компьютер, который мейнтейнер или другой владелец зарегистрировал в Effector, с подключённым последовательным адаптером.
- **Машина на кабеле** — цель: PinePhone, плата, ПК.
- **Один порт — один режим одновременно** (раздел 3).

## 3. Два режима порта

| | `console` | `link` |
|---|---|---|
| Что идёт по линии | байты как есть, в обе стороны | кадры MIND Link ([протокол](link/protocol_RU.md)), хост — ведущий |
| Другой конец | любая система | `link` в MIND Core или `mindlink serve` |
| Что получает сессия | терминал: вывод от курсора, ввод, break, DTR и RTS | операции effector485 (put, get, list, log, run, shell, reboot, replace и остальные) для каждой машины на кабеле, и консоль каждой машины через канал 1 link |
| Несколько машин на одной линии | нет | да, на RS-485, по их адресам |

- **Режим переключается явно** — сессией, которая держит аренду порта (раздел 4.3).
- **Байты вне кадров link** показываются как консоль и в режиме `link`. Это первые строки загрузки, до того как `link` ответит (раздел 5.1).

## 4. Часть агента Effector, для Linux и Windows

Эту часть `EFF` передаёт проекту Effector. Агенты сервера написаны на Go (`agent/linux/worker.go` в `sst-test-deploy`). Имена вызовов ниже — предложение этой страницы. Проект Effector выбирает свои, и то, как они идут между сервером и агентом.

### 4.1 Порты и политика владельца

- **Опись последовательных портов**, в составе конечных точек агента; у каждого порта:
  - стабильная идентичность: в Linux `/dev/serial/by-id/…` (производитель USB, продукт, серийный номер, интерфейс) и существующие `/dev/ttyS*`; в Windows имя `COMn` с путём экземпляра устройства (SetupAPI: производитель, продукт, серийный номер);
  - есть ли он и занят ли, кем (сессией или другой программой).
- **Политика владельца — файл на хосте,** который ничто с сервера не меняет. Для каждого порта:
  - предлагается ли он вообще, и его имя для сессий (`phone-uart`, `rs485-bus`);
  - разрешённые режимы (`console`, `link`) и разрешённые настройки линии (список скоростей);
  - **может ли сессия писать в консоль:** по умолчанию нет. Консоль всесильна: приглашение U-Boot перезаписывает флеш, оболочка выполняет команды;
  - **можно ли управлять DTR, RTS и break:** по умолчанию нет, они сбрасывают некоторые платы;
  - **в режиме `link` — разрешённые виды операций:**
    - по умолчанию только читающие: `hello`, `log`, `list`, `stat`, `get`;
    - пишущие и требующие режима разработчика MIND Core (`put`, `mkdir`, `move`, `delete`, `rmdir`, `run`, `install`, `uninstall`, `reboot`, `shell`, `replace`, `key`, `type`) — только если владелец их перечислил;
  - адреса на паре RS-485 и идентификаторы, которые получают машины (раздел 4.4);
  - сколько хранит запись (раздел 4.3).
- **Порт, занятый другой программой, показывается занятым и никогда не отбирается.**
  - Linux: `TIOCEXCL` и блокировка устройства.
  - Windows: `CreateFile` без совместного доступа.
- **Linux:** пользователь агента должен быть в `dialout`. Это шаг root, который владелец хоста делает один раз. В заметках по установке это сказано.

### 4.2 Линия

- **Настройки:**
  - скорость: какую берёт адаптер, от 300 до 3 000 000; по умолчанию 115200. В Linux — `termios2` с `BOTHER` для скоростей вне стандартного списка;
  - биты данных от 5 до 8; чётность: нет, чёт, нечёт, mark или space; стоп-биты 1, 1,5 или 2;
  - управление потоком: нет, RTS/CTS или XON/XOFF.
- **Направление RS-485, для каждого порта в политике:**
  - `auto`: преобразователь переключает его сам (TXDEN у FTDI, преобразователи с автоматическим направлением). Это значение по умолчанию и поначалу единственное в Windows;
  - `rts`: передатчиком управляет RTS, с задержками до и после передачи в миллисекундах. Linux: `TIOCSRS485`. Windows: `RTS_CONTROL_TOGGLE`;
  - фильтр эха для двухпроводных преобразователей, которые возвращают переданное.
- **Когда применяются.** Настройки применяются при открытии порта. Пока он открыт, менять их может только держатель аренды порта, а состояние сессии их показывает.

### 4.3 Консольная сессия

- **Открытие.** Вызов называет:
  - агента, порт и режим `console`;
  - настройки;
  - `reason` и `idempotency_key`, как у каждой операции Effector.

  Читать порт могут несколько сессий. Пишет только держатель его аренды.
- **Аренда порта** — как терминальные резервирования Effector: одна за раз, со сроком, продлением и освобождением; владелец и причина видны всем. PIN никогда не пишется в журнал.
- **Что присылает порт:**
  - Это попадает в кольцо, которое держит агент, с абсолютными смещениями байтов: не меньше 1 МиБ на порт, старое уходит первым.
  - Ещё это пишется в файл записи на хосте, с ротацией на размере из политики.
  - Так ничего не теряется, пока никто не смотрит. Вернувшийся читатель читает от своего курсора.
  - Читатель, спросивший от уже выброшенного смещения, получает самые старые сохранённые байты и число потерянных (`gap`).
  - У каждого куска хранится время прихода (часы хоста, в миллисекундах), чтобы консоль можно было сопоставить с другими событиями машины.
- **Что пишет сессия:**
  - Каждый вызов несёт байты (base64) или текст и порядковый номер.
  - Записи уходят по порядку. Вызов, присланный дважды, пишется один раз: повтор отклоняется на агенте, на той границе, что принимает ввод порта (MC-7.5).
  - `pace_ms` между символами — для консолей, которые теряют быстрый ввод. U-Boot на 115200 без этого теряет вставленную строку.
  - Один вызов — не больше 4 КиБ.
- **Управление:**
  - break с длительностью в миллисекундах;
  - установка или импульс DTR и RTS;
  - смена настроек линии;
  - сброс буферов.
- **Вживую:**
  - Поток на каждую сессию (WebSocket или длинные опросы сервера) несёт вывод по мере прихода и принимает ввод.
  - Агент пересылает пришедшее в пределах 100 мс, пачками.
  - Цель — эхо нажатой клавиши через сервер за полсекунды. Это надо измерить и сообщить, а не обещать. Удалённая консоль — не локальная (MC-7.1): сессия видит состояние линии, а потеря связи показывается, а не прячется.
- **Конец:**
  - вызов, который её закрывает;
  - ни одного читателя дольше времени простоя из политики (по умолчанию 30 минут);
  - остановка агента;
  - адаптер выдернут: состояние сессии становится `lost`, со временем. Когда то же устройство (тот же by-id или путь экземпляра) вставлено снова, агент открывает его снова и говорит об этом.
- **Аудит.** Агент записывает каждую запись, break, изменение DTR или RTS и смену настроек, с:
  - сессией и её причиной;
  - владельцем ключа.

  Запись принадлежит владельцу хоста. Она хранится на хосте и читается через журналы агента.

### 4.4 Режим link

- **Реализация протокола остаётся одна** — `LNK`. Агент не добавляет вторую.
  - **Предлагается:** агент запускает `effector485 daemon <порт> --baud … --addresses … --listen 127.0.0.1:<свой порт> --key-file <файл, который читает только пользователь агента>` как подчинённый процесс, по одному на каждый порт в режиме `link`, и вызывает его API ([effector485_RU.md](link/effector485_RU.md), «API»).
  - effector485 уже собирается для Linux и Windows (`tools/mindlink/build.sh`).
  - Агент на Rust мог бы вместо этого подключить крейт `mindlink` (MIT OR Apache-2.0).
- **Что видит сервер:** каждую машину на кабеле как отдельную конечную точку.
  - Её идентификатор — идентификатор агента хоста с `link` или `link-<n>` после него. Точную форму выбирает проект Effector.
  - Её состояние (на связи, имя, последний ответ) берётся из `GET /api/v1/endpoints` effector485.
- **Операции:**
  - **API операций сервера** несёт виды effector485 с их полями (`link.put`, `link.run`, `link.log` …). Агент передаёт их effector485 вместе с `idempotency_key` и `reason` как есть.
  - **Что возвращается:** вывод и состояние (`queued`, `running`, `completed`, `failed`, `cancelled`, `timeout`, `lost`).
  - **Файлы идут в два прыжка:**
    - `put`: файл сначала приходит на хост собственной передачей файлов сервера, потом effector485 отправляет его дальше. SHA-256 проверяется на обоих прыжках;
    - `get`: в обратную сторону.
- **Аренды.** Аренда Effector на такой конечной точке — это аренда effector485 на этой машине, по правилам effector485:
  - работа других ждёт в очереди с указанием, ради кого;
  - чтения проходят.
- **Консоль в режиме `link`** — канал 1 машины через effector485. Агент предлагает её как консольную сессию с API раздела 4.3. Для этого в API effector485 нужен поток консоли (раздел 5.1).
- **Два замка:**
  - **На хосте:** агент отклоняет вид, которого нет в политике его владельца (`denied`, с причиной), прежде чем его увидит effector485.
  - **На машине:** собственный `link.conf` MIND Core (`run`, `dev`) по-прежнему решает, что там выполняется.

### 4.5 Безопасность

- **Новой двери в хост нет.**
  - Всё это несут уже существующие токен и канал агента к серверу.
  - effector485 слушает только loopback, с файлом ключа, который читает только пользователь агента.
- **Секреты.** Ключ сессии и PIN аренды никогда не попадают в URL или журнал.
- **Устаревший держатель отклоняется (MC-7.4).** Записи и управление несут сессию аренды. Когда аренда кончилась или перешла к другой сессии, агент отклоняет записи старой.
- **Когда сервер недоступен (MC-7.6):**
  - агент продолжает запись и никогда ничего не посылает в линию сам;
  - начатая операция link идёт на хосте до конца. Её результат хранится надёжно и сообщается, когда сервер вернётся, до подтверждения — как прочие результаты агента.
- **Уязвимости.** Их подробности идут мейнтейнеру закрыто ([SECURITY.md](../SECURITY.md)).

### 4.6 Платформы и адаптеры

- **Linux:**
  - `termios2`, `TIOCSRS485`, `/dev/serial/by-id`;
  - пользователь агента в `dialout`.
- **Windows:**
  - имена: `\\.\COMn` (COM10 и выше требуют префикса);
  - ввод-вывод: перекрывающийся (overlapped), с `SetCommState` и `SetCommTimeouts`;
  - линии управления: `EscapeCommFunction` для DTR и RTS, `SetCommBreak` и `ClearCommBreak` для break;
  - идентичность устройства из SetupAPI.
- **WSL.** USB-адаптер принадлежит Windows, поэтому его держит агент в Windows. `usbipd` — только если так выберет владелец.
- **Для проверки:**
  - FTDI FT232R и FT232H, CH340, CP2102;
  - преобразователи RS-485 мейнтейнера (главная задача [800](../issues/800-mind-link.md), [800-LNK-0002](../issues/800-LNK-0002-usb-serial-ftdi-and-ch340.md));
  - последовательный кабель PinePhone (гнездо наушников, только **3,3 В** TTL, 115200 8N1).

### 4.7 Тесты в проекте Effector

- **Без железа:**
  - **Стенд:** пара псевдотерминалов (Linux) или com0com (Windows), с `mindlink serve` на дальнем конце для режима `link`.
  - **Консоль:** эхо, читатель, вернувшийся от своего курсора после обрыва, `gap` кольца, запись, присланная дважды и записанная один раз, отклонённый устаревший держатель, закрытый дальний конец как выдернутый адаптер.
  - **Link:** `put`, `run` с выводом, `log` и аренда.
- **На кабеле:**
  - два TTL-адаптера, соединённые друг с другом;
  - два преобразователя RS-485 на одной паре с двумя `mindlink serve` по адресам 1 и 2;
  - потом PinePhone.

## 5. Часть MIND Core

### 5.1 `LNK`: link и effector485

- **Уже запрошено (2026-11-08, [requests-LNK.md](../issues/requests-LNK.md)):** `link` на консольном UART платы, с:
  - консолью оболочки как каналом 1 ([800-LNK-0019](../issues/800-LNK-0019-the-link-as-the-owners-console.md));
  - первыми строками загрузки, читаемыми до того, как link ответит.
- **effector485 как движок агента** (запрошено вместе с этой страницей):
  - **Поток консоли для каждой машины** в его API: вывод канала 1 со смещениями байтов от курсора и ввод с порядковыми номерами. Показывать его смогут и агент, и собственная страница effector485.
  - **Байты вне кадров**, строки загрузки, отдаются как текст консоли со смещениями.
  - **Подчинённый режим:**
    - запуск другой программой;
    - только loopback, файл ключа обязателен;
    - страница не нужна;
    - завершение вместе с родителем.
  - **API с версией**, на который агент может опираться:
    - его версия в `GET /api/v1/version` (или в `hello`);
    - список изменений;
    - новая версия при изменении полей (MC-12.4);
    - виды операций в машиночитаемом списке, для политики агента.
- **Правило 2026-10-30** в effector485.md («локально, намеренно») получает добавление мейнтейнера от 2026-11-08: локально, а также через агента хоста Effector по политике владельца этого хоста. Сессии по-прежнему никогда не обращаются к порту демона напрямую.

### 5.2 `EFF`: передача и собственный агент MIND Core

- **Проекту Effector:** раздел 4, отдельной задачей (рядом с его задачей 81 об агенте MIND Core).
- **Обратно от него:**
  - выбранные имена и то, как потоки идут между сервером и агентом;
  - ревизия агента;
  - шаги установки для владельца хоста.
- **docs/effector.md** получает раздел о последовательных портах, когда сервер и агент начнут их обслуживать, с машинами, у которых есть кабель, и тем, что на нём.
- **Позже, для телефона не нужно:**
  - собственный `effector` MIND Core даёт тот же контракт консоли, чтобы машина MIND Core с USB-адаптером могла быть хостом кабеля другой машины;
  - он делал бы это через `usb_serial` (`idl/serial.wit`).

### 5.3 Сессия ядра: UART платы

- **UART платы из device tree:** [100000-PRT-0009](../issues-done/100000-PRT-0009-the-board-from-the-device-tree.done).
- **16550 в памяти:** [100000-PRT-0010](../issues/100000-PRT-0010-a-16550-uart-in-memory.md). Это касается строк ядра и строк загрузчика.
- **UART отдаётся `link`,** а не оболочке, когда так сказано в `link.conf`: [100000-KRN-0171](../issues/100000-KRN-0171-platform-devices-from-the-device-tree.md).
- **Сначала в QEMU:** `virt` с UEFI от U-Boot и без ACPI (как Tow-Boot даёт телефону), его PL011 на псевдотерминале. Тесты агента тоже могут с ним работать.

| S2 | режим `link` с effector485 как движком (4.4, 5.1) | обновления, журналы и тесты на телефоне: `put`, `get`, `log`, `run`, `reboot`, `replace` |
| S3 | несколько машин на одной паре RS-485; направление через RTS | стенд RS-485 мейнтейнера |
| S4 | MIND Core как хост (5.2, позже) | машина MIND Core как хост кабеля другой машины |

**Свидетельства** каждого этапа называют свою конфигурацию: систему хоста, адаптер, скорость и машину на кабеле (MC-12.1). Прогон на одном адаптере или хосте не переносится на другой.

# Сервер выпусков, `httpd`

**Версия:** 0.3 (2026-11-12) · **Трек:** `NET` ([TRACKS.md](../../TRACKS.md)), основная задача [110](../../issues/110-our-own-web-server.md) · **English:** [server.md](server.md)

`tools/httpd` — собственный веб-сервер проекта для выпусков: программа для Linux, которая отдаёт раскладку `scripts/release.py` только на чтение. Это этап 1 задачи [110](../../issues/110-our-own-web-server.md). Проверки `update` и `update_store` в QEMU идут против него ([110-NET-0068](../../issues-done/110-NET-0068-the-update-checks-run-against-httpd.done)); ни одна настоящая машина ещё не обновлялась с него.

## Чему он доверен, а чему нет

- **Не подлинности обновления.** Выпуск подписан ключом загрузки и ключом выпуска, и устройство проверяет оба (MC-9.6). Взломанный сервер не может его подделать.
- **Он может задержать или не отдать выпуск.** Это ограничивает срок годности канала ([351-UPD-0025](../../issues-done/351-UPD-0025-expiry-and-the-offline-policy.done)).
- **Он хранит ключ TLS, который устройства закрепляют.** Тот, кто завладел ключом, может выдать себя за сервер, но подделать выпуск всё равно не может.

## Сборка и запуск

```
cd tools/httpd && cargo build --release
target/release/httpd /srv/mind --cert chain.pem --key key.pem --listen 0.0.0.0:443 --log /var/log/mind-httpd
```

- **Корень** — каталог, в который пишет `release.py publish`: `blobs/`, `releases/`, `channels/`. Ничего другого под ним не отдаётся: каждое имя сверяется со своим образцом, а ссылки, имена с точки, запросы с параметрами и закодированные байты отвергаются.
- **Публикация не меняется.** `publish` пишет по SSH и переименовывает канал последним. Каждый запрос открывает свой файл один раз, поэтому читатель получает старый канал или новый целиком.
- **Без `--cert` и `--key`** сервер говорит на открытом HTTP — для закрытой сети или теста.

## TLS и закрепление ключа

- **Только TLS 1.3,** с AES-GCM и ChaCha20-Poly1305, X25519 и P-256: rustls 0.23 поверх крейтов RustCrypto, как в сервисе `tls` ([THIRD_PARTY.md](../../THIRD_PARTY.md)).
- **Ключ:** ECDSA P-256 или Ed25519, в PEM PKCS#8 или SEC1. Ключ RSA загружается только с `--allow-rsa`: подпись крейта `rsa` не постоянна по времени (RUSTSEC-2023-0071), поэтому он только для тестовых сертификатов.
- **Закрепление.** При запуске сервер печатает `HTTPD: TLS 1.3, THE KEY'S SPKI SHA-256 <hex>`. Это значение принимает `pin` в `update.txt` ([updater_RU.md](updater_RU.md)).
- **Продление сохраняет ключ.** Сервер перечитывает сертификат и ключ, когда их файлы меняются; проверка раз в 10 с. Уже открытые соединения остаются со старым сертификатом.
  - Новый сертификат на тот же ключ: `HTTPD: THE CERTIFICATE RELOADED, THE SAME KEY`.
  - Новый ключ: сервер говорит об этом, потому что устройство, закрепившее только старый ключ, его отвергнет. Новый ключ публикуется вторым закреплением до того, как его начинают использовать ([351-UPD-0031](../../issues/351-UPD-0031-key-lifecycle-and-compromise-protocol.md)).
  - Пара, которая не загружается, или ключ не от этого сертификата: остаётся прежняя пара, и сервер говорит почему.

## Пределы

Каждый отказ называет предел, в который упёрся, в ответе и в журнале.

| Флаг | По умолчанию | Отказ |
|---|---|---|
| `--connections` | 64 одновременно | 503 (по TLS соединение закрывается) |
| `--per-client` | 8 одновременно с одного адреса | 503 (так же) |
| `--per-minute` | 600 запросов с адреса | 429, с `Retry-After` |
| (постоянно) | заголовок до 8 КиБ, 64 строки | 431 |
| `--head-timeout` | 10 с на заголовок запроса | 408 |
| `--idle-timeout` | 10 с между байтами заголовка | 408; соединение, простоявшее столько между запросами, закрывается |
| `--send-timeout` | 30 с на запись, которую клиент не принимает | соединение закрывается |

## Журнал

- Одна строка на запрос: время, адрес клиента, метод, путь, статус, отправленные байты, длительность и причина отказа.
- Один файл в день, `httpd-YYYY-MM-DD.log`, в `--log`; файлы старше `--log-days` (30) удаляются. Без `--log` строки идут в стандартный поток ошибок.
- В нём никогда нет строки запроса или значения заголовка; байты вне алфавита имён показаны как `?`.

## Крючки для тестов

Проверкам в QEMU нужен сервер, который обрывает загрузку посередине, задерживает ответ и записывает, что у него просили ([110-NET-0068](../../issues-done/110-NET-0068-the-update-checks-run-against-httpd.done)). Эти крючки собираются только с признаком Cargo `test-hooks`; сервер без него отвергает `--test-hooks`.

- **`--test-hooks DIR`.** Имя пути там — путь без первого `/`, где каждый `/` заменён на `+`.
  - `DIR/cut/<имя>` хранит число байтов: следующий ответ на этот путь обрывается после стольких байтов тела, и его соединение закрывается.
  - `DIR/hold/<имя>`: следующий ответ на этот путь ждёт, пока есть `DIR/held/<имя>` сервера, не дольше 10 с.
  - `DIR/requests`: строка на запрос, его путь и заголовок `Range` (`-`, если его нет).
- **`scripts/serve_httpd.py`** собирает его так и запускает для наборов `update` и `update_store`. Они ставят его сроки в 60 с, потому что эмулируемые машины на нагруженной машине медленны.
- `scripts/serve_release.py` остаётся для проверок загрузок набора `net`, которым нужен испорченный заголовок, какого настоящий сервер не шлёт.

## На машине MIND (этап 2)

`httpd` есть и как служба MIND Core: она раздаёт ту же раскладку с машины MIND ([110-NET-0070](../../issues-done/110-NET-0070-httpd-as-a-mind-core-service.done)). Она следует правилам `tools/httpd` (`mind::http_serve`, с теми же случаями в хост-тестах); отличия ниже.

- **Запускается `init`**, только если политика даёт программе `httpd` право слушать: `listen httpd tcp 443 from <сеть>/<префикс>`. Без него `init` пишет `httpd NOT STARTED: THE POLICY GIVES IT NO LISTENING GRANT`.
- **Содержимое:** `data/releases/` владельца (`blobs/`, `releases/`, `channels/`), которое `init` даёт только для чтения и никогда не создаёт. Без него на любой путь ответ 404.
- **Только TLS 1.3, на TCP 443.** Рукопожатие ведёт служба TLS ([110-NET-0069](../../issues-done/110-NET-0069-the-tls-services-server-role.done)), а каждую подпись ключом устройства делает `keystore`; ключ его не покидает (MC-11.9).
  - Сертификат — сертификат устройства (Ed25519, самоподписанный) или цепочка из `tlsserver.pem` на загрузочном диске, первый сертификат которой должен нести ключ устройства.
  - Устройство закрепляет SHA-256 его SPKI; сам сертификат печатает `tls cert`.
  - Браузеры не принимают серверный сертификат Ed25519: этот сервер — для машин (curl, OpenSSL, собственный клиент MIND Core).
- **Заголовки запросов** разбирает служба разбора (`parse.wit` 2.1 `http-request`, MC-11.11), а не `httpd`.
- **Пределы:**
  - 7 соединений сразу, 4 с одного адреса;
  - заголовок не больше 8 КиБ и не дольше 10 с от первого байта;
  - 10 с без принятого байта или на простаивающем сохранённом соединении;
  - 600 запросов в минуту с одного адреса;
  - рукопожатие TLS не дольше 10 с.
- **Журнал** — системный: `[HTTPD] <клиент> <метод> <путь> <статус> <байты> <мс> MS (<почему>)`, без строки запроса и без значений заголовков.
- **Крючков для тестов нет:** у службы MIND их нет.

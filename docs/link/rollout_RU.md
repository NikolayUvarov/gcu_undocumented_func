# Раскатка: один выпуск, по одной машине

English: [rollout.md](rollout.md).

`scripts/rollout.py` отдаёт один выпуск нескольким машинам по очереди. Следующей машины он касается, только когда агент Effector этой машины вернулся на сервер с этим выпуском. Задача: [801-LNK-0045](../../issues/801-LNK-0045-a-rollout-one-machine-at-a-time-and-the-cable-on-all.md), для условия S8 задачи 801.

## Запуск

```bash
# Пробный прогон: выпуск собирается локально, сервер и кабель только читаются.
TMPDIR=/mnt/c/common_virtual/Culture/mindlink/tmp-upd \
scripts/rollout.py --root usb_root mind_353abc18de2dbd0e mind_09dca8b4def0f6e6 mind_bc5d2f3b851df7a6 \
    --cable mind_353abc18de2dbd0e --mindlink ADAPTER --dry-run

# Сама раскатка: та же строка без --dry-run.
```

**Выпуск:**
- `--root DIR`, подписанная сборка, становится выпуском `--version` (по умолчанию время в виде `YYYYMMDDHHMM`), как его делает `link_update.py`. Затем пишется его пакет, как его пишет `release.py bundle`.
- `--bundle FILE` — уже готовый пакет. Его канал называет версию, и он проверяется, как `release.py check` проверяет дерево сервера.

Всем машинам идёт один и тот же выпуск.

**Машины** — идентификаторы агентов Effector, по порядку. Пока ничего не отправлено, скрипт отказывает машине, названной дважды, машине, которой сервер не знает, и машине с процессором не того выпуска.

**Сервер** — `--server` (`https://hesere.uz/effector`).
- API-ключ оператора читается из `--key-file` (`~/.config/mind-effector/hesere/api_key`).
- Он идёт в заголовке `Authorization` и больше никуда.
- Он идёт только по HTTPS или на петлю этой же машины и никогда не следует перенаправлению.
- Каждая строка, которую печатает скрипт, проверяется на ключ.

**Кабель** используется только для машины, названной в `--cable`:
- `--port` (`COM22`) и `--mindlink` идут в `link_update.py`, как в [mindlink_RU.md](mindlink_RU.md).
- Пока порт держит `effector485`, `--mindlink` — переходник, который превращает `hello`, `mkdir`, `put` и `log` в `effector485 submit … --wait` (свой у стенда; в репозитории его пока нет).
- Аренду, если она нужна, держит переходник (`E485_LEASE_FILE`).
- `TMPDIR` должен быть папкой, которую читает демон в Windows: файлы выпуска кладутся оттуда.

**Срок** — `--wait` (1200 с), от отправки выпуска до возвращения агента. `--poll` (10 с) — как часто спрашивать сервер.

**`--run-id`** образует ключи идемпотентности операций (по умолчанию время запуска). При повторном запуске с тем же ID скрипт находит уже начатые им операции.

## Для каждой машины

1. **Через сервер**, когда конечная точка в сети и принимает операции (`online` и `operations_ready` в `GET /api/v1/endpoints?id=…`):
   - пакет загружается один раз, `POST /api/v1/files`;
   - затем `POST /api/v1/operations` отправляет `kind` `update_agent`, `artifact_id`, `version`, `timeout_seconds` и `queue_ttl_seconds` (срок, не больше 3600), `idempotency_key` и `reason`;
   - затем операция читается до её конца.
2. **По кабелю**, когда сервер не достаёт машину или её агент не принял `update_agent`. «Не принял» — это ответ, пришедший раньше, чем хоть один байт дошёл до обновителя: `denied` (`remote-update` выключен или в политике владельца нет `update apply`), `no-policy`, `expired` или отказ сервера. Кабель используется только для машины, названной в `--cable`, и только после того, как её журнал по кабелю называет этого агента:
   - последняя строка `EFFECTOR: AGENT <id> TO …` или `NEW AGENT ID <id>`;
   - если журнал называет другого агента или никакого (кольцо могло потерять строку запуска агента), ничего не отправляется.

   Затем `link_update.py` кладёт выпуск и следит за строками обновителя до `SLOT S CONFIRMED ON THE DISK`, отказа или отката.

### Вернулась

Машина вернулась, когда выполнено всё это:
- **Её ответ.** Через сервер `update_agent` ответил `completed`, `updated N, slot S confirmed`. По кабелю обновитель подтвердил слот.
- **Сервер.** Конечная точка снова в сети и принимает операции.
- **Её кольцо.** Затем скрипт читает журнал этой загрузки, `collect_logs` от `ring`, который по определению этой загрузки. Сохранённый журнал `boot` в первые минуты загрузки может быть ещё журналом предыдущей. В кольце:
  - `[UPDATER] SLOT S[ ON TRIAL], VERSION N` должен называть выпуск N;
  - с `--commit` строка `[INIT] BUILD: BRANCH …, COMMIT …` должна называть этот коммит.

  Строки печатаются как свидетельство.

**Поздний ответ.** От позднего ответа сервер хранит только статус (`late_acknowledgement`), без текста. Тогда выпуск доказывает строка версии в кольце.

### Она останавливает раскатку

Скрипт печатает машину, причину и строки её журнала: кольцо этой загрузки и новейший сохранённый журнал загрузки, или кольцо по кабелю. Следующих машин он не касается. Он останавливается, когда:
- **Машина откатилась:** `failed`, `fell-back`, `fell back: slot S runs version V, not N; the updater: …`. После S1 и S2 задачи 801 обновитель этой загрузки пишет `[UPDATER] A TRIAL REFUSED BEFORE (system/updater/refused): …` с шагом, который не прошёл.
- **Выпуск отвергнут или не подтверждён:** `digest`, `signature`, `older`, `version`, `not-confirmed`, `restart`, `io` и остальные. Это отказы уже за дверью обновителя.
- **Машина не вернулась в срок.**
- **Её кольцо называет другую версию или коммит.**
- **По кабелю:** строка обновителя `REFUSED` или `ROLLBACK`, или нет подтверждения в срок.
- **Нет пути:** сервер не достаёт машину, и она не та, что на кабеле.

Код выхода: 0, когда вернулась каждая машина, 1, когда раскатка остановилась, 2 при ошибке использования или выпуске, который не проходит проверку.

## Тесты

`tests/rollout_test.py`, который запускает `scripts/host_tests.sh`, гоняет скрипт против заменителя сервера на `127.0.0.1`. Заменитель отдаёт маршруты и поля, описанные выше, так, как их отдаёт hesere. Случаи:
- три машины обновлены по порядку, каждой выпуск отправлен только после ответа предыдущей, одной из них поздним ответом, доказанным её кольцом;
- откат останавливает раскатку до третьей машины, с причиной и строками обновителя;
- машина, которая не возвращается, останавливает её по сроку;
- машина, которую сервер не достаёт и которой нет на кабеле, останавливает её;
- пробный прогон делает только GET-запросы и читает только журнал кабеля;
- неизвестная машина или неверный ключ ничего не отправляют;
- ключ никогда не печатается, и по простому HTTP на другой хост он не идёт;
- машина, чей агент ответил `denied`, идёт по сценарному кабелю, когда её журнал её называет, и возвращается;
- кабель, достающий другую машину, ничего не получает.

Это только свидетельство на хосте: настоящий сервер и машины не использовались (MC-12.1). Прогон на стенде — за задачей.

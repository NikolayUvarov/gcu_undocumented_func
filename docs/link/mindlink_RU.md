# mindlink: конец связи на Linux и WSL

English: [mindlink.md](mindlink.md).

`mindlink` говорит на [протоколе MIND Link](protocol_RU.md) через последовательный порт. Задача: [800-LNK-0004](../../issues/800-LNK-0004-mindlink-the-host-tool.md).
- **Как ведущий:** передаёт файлы и каталоги, запускает программы и читает их вывод, читает журнал другого конца и печатает в его консоль.
- **[effector485](effector485_RU.md)**, собранный рядом с ним, ставит такую работу в очередь операций, которые агенты отдают и к которым потом возвращаются.
- **Как `serve`:** играет ведомого над каталогом, поэтому линию можно проверить между двумя концами на Linux раньше, чем появится конец в MIND Core (800-LNK-0003).

## Сборка

```bash
tools/mindlink/build.sh
# Linux и WSL:  tools/mindlink/target/release/mindlink
# Windows:      tools/mindlink/target/x86_64-pc-windows-gnu/release/mindlink.exe
```

- **Она использует только стандартную библиотеку и `linkproto`.**
- **В Linux** последовательный порт настраивается через termios из glibc.
- **В Windows** порт COM настраивается через вызовы связи Win32. Программе не нужны DLL, кроме системных.
- **Сборка для Windows** перекрёстная. Ей нужны `rustup target add x86_64-pc-windows-gnu` и компоновщик MinGW-w64.

## Команды

```text
mindlink [параметры] <порт> <команда> [аргументы]
```

Параметры идут перед командой; всё, что после команды, принадлежит ей, в том числе аргументы программы.

**Имена** на другом конце — пути внутри его каталога, части которых соединены `/` (`apps/test/x.elf`), и ни одна не `.` и не `..` ([протокол, раздел 5](protocol_RU.md#5-запросы)). Старый конец принимает только одну часть.

**Порты:**

| Порт | Что это |
|---|---|
| `/dev/ttyUSB0`, `COM10` | последовательный порт в Linux или Windows в сыром режиме (8 бит, без чётности, без управления потоком) на скорости `--baud` |
| `tcp:HOST:PORT` | соединение TCP, например с последовательным chardev в QEMU |
| `listen:PORT` | ждёт одного соединения TCP; `listen:0` выбирает порт и печатает его |
| `pty` | только для `serve`, Linux: псевдотерминал для тестов; печатает свой путь |

**Команды:**

| Команда | Что делает |
|---|---|
| `hello` | имя другого конца, версия протокола и размер нагрузки; на порту FTDI предупреждает, если таймер задержки замедляет ответы |
| `put <файл> [<имя>] [--force]` | посылает файл. Пропускает, если у другого конца те же байты (его SHA-256), кроме `--force`. Прерванная запись с тем же именем и размером продолжается |
| `get <имя> [<файл>]` | забирает файл в `<файл>.part` и переименовывает, когда SHA-256 совпал |
| `ls [<каталог>]` | файлы каталога с размерами и его каталоги, с `/` на конце; без `<каталога>` — верхний уровень |
| `stat <имя>` | размер файла и его SHA-256 |
| `rm <имя>`, `delete <имя>` | удаляет файл |
| `mkdir <каталог>` | создаёт каталог и недостающих родителей |
| `mv <откуда> <куда> [--force]` | перемещает или переименовывает файл или целый каталог; `--force` заменяет файл на месте `<куда>` |
| `rmdir <каталог> [-r]` | удаляет пустой каталог; `-r` — со всем содержимым |
| `run <программа> [<аргумент>...]` | запускает программу из каталога другого конца и показывает её вывод до её завершения. Выходит с её кодом завершения, если другой конец его знает, и с 1 после сбоя. В MIND Core в `link.conf` должно быть слово `run` |
| `start <программа> [<аргумент>...]` | то же, но печатает только номер запуска и PID программы |
| `sh <строка>` | одна строка для оболочки другого конца и её вывод; выходит с 1, когда оболочка её отвергла или та не удалась. MIND Core: `dev` в `link.conf` (800-LNK-0015) |
| `replace <служба> <файл> [<имя>]`, `replace <служба> --back` | кладёт файл (как `replace/<его имя>`) и запускает службу другого конца заново из него, без проверки подписи; `--back` возвращает её образ загрузки. MIND Core: `dev` в `link.conf` (800-LNK-0016) |
| `out <запуск> [-f]` | вывод запуска, который другой конец ещё хранит; `-f` следит за ним до завершения |
| `runs` | запуски, которые знает другой конец: номер, PID, состояние, программа |
| `stop <запуск>` | завершает программу запуска |
| `reboot` | перезапускает машину другого конца. В MIND Core в `link.conf` должно быть слово `dev` |
| `log [-f]` | журнал другого конца; `-f` следит за ним |
| `console` | строки со стандартного ввода в консоль другого конца, её вывод обратно; Ctrl-D завершает |
| `sniff [<секунды>]` | сырые байты линии в шестнадцатеричном виде, по мере прихода (по умолчанию 10 с): на паре RS-485 слушайте один преобразователь, пока другой передаёт, чтобы проверить проводку и скорость |
| `board <строка>` | одна строка в порт управления платы [мультиустройства](multi-device_RU.md) (`type …`, `key …`, `move …`, `status`) и её ответ |
| `serve <каталог> [--log <файл>] [--console <команда>] [--run]` | ведомый: файлы в `<каталоге>` и его подкаталогах, журнал из `<файла>`, консоль, в которой работает `<команда>` через `/bin/sh -c`. Без `--console` консоли нет. `--run` позволяет ведущему запускать программы из `<каталога>` от имени пользователя, запустившего `serve`: это не хуже оболочки для того, кто держит кабель. Программа, присланная по связи, получает бит исполнения владельца, когда её запускают |

**Параметры:**

| Параметр | По умолчанию |
|---|---|
| `--baud <скорость>` | 115200. Скорости от 9600 до 3000000, которые есть в Linux (921600, 2000000 и другие). На обоих концах скорость должна быть одна |
| `--timeout <мс>` | сколько ждёт одна попытка: по скорости на последовательном порту, 2 с на TCP |
| `--tries <n>` | 8 попыток на каждый запрос |
| `--turnaround <мкс>` | `serve`: 500 мкс перед каждым ответом, чтобы преобразователь RS-485 переключил направление линии |
| `--payload <байты>` | 1024: наибольшая нагрузка кадра, от 64. Меньше для зашумлённой линии и 256 для эмулированного преобразователя QEMU (ниже) |
| `--address <n>` | нет: линия с одной машиной. На линии, общей для нескольких (ниже): адрес другого конца, от 1 до 247; с `serve` — свой адрес |

О каждом переданном файле выводятся размер, время, скорость и SHA-256. Об отказе или отсутствии ответа выводится причина, и код выхода — 1.

**Метка на экране MIND Core** (800-LNK-0020). Пока по линку слышен ведущий, `link` в MIND Core зажигает в правом верхнем углу экрана кольцо с точкой:
- **красное**, если в `link.conf` есть `dev`: ведущий может менять машину;
- **жёлтое**, если `dev` нет: ведущий может только читать;
- **серое**, когда ведущий молчит 5 с. Когда `link` останавливается, метка исчезает.

Метку рисует композитор, поэтому её нет на снимках экрана и никакая другая программа не может её зажечь (800-KRN-0156). `effector485` держит линию живой, отправляя POLL каждые 2 с, так что между его операциями метка не гаснет. Команда `mindlink` зажигает её только на время своей работы.

## Преобразователи в Windows

`mindlink.exe` работает с преобразователем под тем именем, которое дала ему Windows, без usbipd:

```text
mindlink.exe --baud 921600 COM10 hello
mindlink.exe --baud 921600 COM10 put build.img
```

- **Диспетчер устройств** показывает номер COM каждого преобразователя.
- **Таймер задержки порта FTDI** — дополнительное свойство порта, по умолчанию 16 мс; 1 мс ускоряет каждый ответ.
- **Порт в WSL не виден в Windows.** Преобразователь, подключённый к WSL через usbipd, пропадает из Windows, пока его не отключат.
- **Из WSL через порт Windows:** `tools/mindlink/mindlink-exe.sh` запускает `mindlink.exe` (`MINDLINK_EXE` или тот, что в PATH). Каждый аргумент, который называет здешний файл, он передаёт как путь Windows. `mindlink.exe` читает файлы WSL как `\\wsl.localhost\…`.
  - Сценарии, которые вызывают `mindlink`, используют его так.
  - Обновление через линк (351-KRN-0141) на MacBook Pro, 2026-10-21:

    ```bash
    MINDLINK_EXE=/mnt/c/…/mindlink.exe scripts/link_update.py COM22 --mindlink tools/mindlink/mindlink-exe.sh \
        --mindlink-option=--baud --mindlink-option=460800
    ```

## Преобразователи в WSL

WSL 2 не видит COM-порты Windows. Преобразователь USB попадает в WSL через [usbipd-win](https://github.com/dorssel/usbipd-win), и тогда Windows его больше не видит.

1. **Установить usbipd один раз** в Windows:
   ```powershell
   winget install usbipd
   ```
2. **Найти преобразователи** (PowerShell от администратора):
   ```powershell
   usbipd list
   ```
   - FTDI FT232R — `0403:6001`; на ПК сопровождающего это был COM4.
   - WCH CH340 — `1a86:7523`; там это был COM10.
3. **Открыть доступ к каждому один раз** по его bus ID из списка:
   ```powershell
   usbipd bind --busid <BUSID>
   ```
4. **Подключить к WSL** каждый раз, когда его вставили. `--auto-attach` держит его подключённым:
   ```powershell
   usbipd attach --wsl --busid <BUSID>
   ```
5. **В WSL** загрузить драйверы, если порт не появился, и разрешить пользователю его открывать:
   ```bash
   sudo modprobe ftdi_sio; sudo modprobe ch341
   ls -l /dev/ttyUSB*
   sudo usermod -aG dialout "$USER"   # затем войти заново; или пока: sudo chmod 666 /dev/ttyUSB0
   ```
6. **На порту FTDI поставить таймер задержки в 1 мс.** Иначе драйвер держит каждый короткий ответ до 16 мс:
   ```bash
   echo 1 | sudo tee /sys/bus/usb-serial/devices/ttyUSB0/latency_timer
   ```

## Подключение RS-485

- **Два провода:** A к A и B к B, и общая земля между машинами, если её нет. Если ничего не проходит, поменяйте A и B местами: производители подписывают их по-разному.
- **На длинном кабеле** — резистор 120 Ом между A и B на каждом конце. Короткий кабель на столе работает без него.
- **Линия полудуплексная.** В протоколе никогда не бывает двух передатчиков. Преобразователям, которые сами переключают направление (TXDEN у FT232R, модули на CH340), больше ничего не нужно.

## Несколько машин на одной линии

Пара RS-485 выдерживает до 32 стандартных нагрузок (больше с преобразователями дробной нагрузки), поэтому один преобразователь у ведущего достаёт до нескольких машин (800-LNK-0026, версия 2 протокола).

- **Подключение:** одна пара от машины к машине, A ко всем A и B ко всем B, с короткими отводами к каждому преобразователю. Резисторы 120 Ом — только на двух дальних концах пары, сколько бы машин ни было между ними.
- **У каждой машины свой адрес** от 1 до 247, без повторов:
  - MIND Core: `address=<n>` в `link.conf` (`scripts/build_and_write.sh --link-address=<n>`). `link` пишет в журнал `[LINK] ADDRESS <n> ON A SHARED LINE` и дальше отвечает только на кадры к этому адресу;
  - `mindlink serve --address <n>`.
- **Ведущий называет машину** в каждой команде: `mindlink --address 2 /dev/ttyUSB0 log`. Команды к разным машинам идут по линии по очереди: протокол отвечает на один запрос за раз.
- **Одна машина без адреса** может остаться на паре, как любая машина до версии 2. Команды без `--address` доходят только до неё.

```bash
mindlink --address 1 --baud 460800 /dev/ttyUSB0 hello     # MacBook, address=1 в его link.conf
mindlink --address 2 --baud 460800 /dev/ttyUSB0 log       # вторая машина на той же паре
```

Свидетельство: тесты на хосте ниже запускают трёх ведомых с адресами и одного без адреса на смоделированной общей линии. Свидетельство для настоящей пары записывается в 800-LNK-0026, когда она измерена (MC-12.1).

## Два преобразователя друг с другом

Первая проверка линии (критерий приёмки 800-LNK-0004): оба преобразователя на одном ПК и соединены друг с другом:

```bash
mindlink --baud 921600 /dev/ttyUSB1 serve ~/link-srv &        # один преобразователь — ведомый
head -c 10M /dev/urandom > /tmp/10M.bin
mindlink --baud 921600 /dev/ttyUSB0 hello
mindlink --baud 921600 /dev/ttyUSB0 put /tmp/10M.bin
mindlink --baud 921600 /dev/ttyUSB0 get 10M.bin /tmp/10M.back
cmp /tmp/10M.bin /tmp/10M.back
```

**Чего ожидать** — это оценка, а не измерение: на линии кадр занимает около 10 бит на байт, поэтому 921 600 бод дают не больше примерно 90 КБ/с. Каждый запрос в 1 КиБ ждёт ответа, поэтому выйдет меньше. Скорости, которых достигнет настоящая пара, записываются в 800-LNK-0004, когда их измерят.

## MIND Core в QEMU

`-device usb-serial` в QEMU эмулирует FTDI FT232, который ведёт `usb_serial` в MIND Core. Если вывести его линию на псевдотерминал, `mindlink` достаёт до службы `link` так же, как через преобразователь:

```bash
qemu-system-x86_64 ... -device qemu-xhci,id=xhci -chardev pty,id=link -device usb-serial,bus=xhci.0,chardev=link
# QEMU пишет: char device redirected to /dev/pts/N (label link)
mindlink --payload 256 /dev/pts/N hello
```

- **Там используйте `--payload 256`.** Эмулированная микросхема держит 384 байта, а QEMU снова наполняет её из псевдотерминала только тогда, когда его главный цикл просыпается по другой причине. Хвост кадра побольше тогда ждёт полсекунды и дольше.
- **Устройство подключено, только пока открыт его chardev.** С `-chardev socket,...,server=on` QEMU подключает устройство, когда приходит клиент, и отключает, когда клиент уходит. Псевдотерминал остаётся открытым.

## Тесты

`tools/mindlink/tests/mindlink.rs` запускает `mindlink` против его собственного `serve`:
- через псевдотерминал, путь termios: каждая команда, по 1,5 МБ в каждую сторону;
- через TCP;
- против остановленного сервера, который должен дать отказ за ограниченное время;
- дерево каталогов создаётся, перемещается и удаляется, и `ls` показывает каждый шаг; программы запускаются с `serve --run`, их вывод и код завершения, остановка; без `--run` ничего не запускается.

`tools/mindlink/tests/bus.rs` запускает три `mindlink serve` с адресами от 1 до 3 и один без адреса, все на одной смоделированной общей линии (TCP-концентратор, который повторяет байты каждого конца остальным): на каждый адрес отвечает только его ведомый, без адреса — только тот, что без адреса, на неизвестный адрес — никто.

`tools/mindlink/tests/effector485.rs` так же проверяет [effector485](effector485_RU.md).

Их запускает `scripts/host_tests.sh`. О настоящем преобразователе или кабеле они ничего не говорят (MC-12.1).

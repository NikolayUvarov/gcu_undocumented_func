# Мультиустройство MIND Link

English: [multi-device.md](multi-device.md).

Мультиустройство — две платы на RP2040 или RP2350, соединённые двумя проводами и землёй ([800-LNK-0005](../../issues/800-LNK-0005-the-rp2-multi-device-firmware.md)). Каждая плата вставляется в USB-порт своей машины. Иначе две машины не могут общаться по USB: обе — хосты. Пара даёт каждой машине:
- последовательный порт к другой машине;
- быстрый порт данных для [`mindlink`](mindlink_RU.md) и его файлов;
- управление клавиатурой, мышью и планшетом другой машины.

Обе платы работают на одной прошивке из `devices/rp2-link/`.

**Состояние (2026-10-20):** прошивка собирается для каждого вида платы, её логика проходит тесты на хосте. На плате она ещё не работала, поэтому ничего на этой странице не измерено. Числа ниже — расчётные.

## Сборка и прошивка

```bash
devices/rp2-link/build.sh                 # все платы, или некоторые: build.sh rp2040-zero rp2350-zero
# devices/rp2-link/dist/mind-link-<плата>.uf2
```

- **Нужны:**
  - `arm-none-eabi-gcc`, `cmake` и `ninja`;
  - Pico SDK 2.2: `$PICO_SDK_PATH` или `/opt/rp2040sens01-toolchain` сопровождающего.
- **Скрипт сначала запускает тесты на хосте.**
- **Прошить:** держа BOOTSEL, вставить плату, затем скопировать её UF2 на появившийся диск.

| Плата | Файл | Светодиод |
|---|---|---|
| Waveshare RP2040-Zero | `mind-link-rp2040-zero.uf2` | WS2812 на GP16 |
| YD-RP2040 | `mind-link-rp2040-yd.uf2` | WS2812 на GP23 |
| Raspberry Pi Pico | `mind-link-rp2040-pico.uf2` | зелёный светодиод на GP25, вкл./выкл. |
| Waveshare RP2350-Zero | `mind-link-rp2350-zero.uf2` | WS2812 на GP16 |
| Raspberry Pi Pico 2 | `mind-link-rp2350-pico2.uf2` | зелёный светодиод на GP25, вкл./выкл. |

Платы пары могут быть разных видов.

## Соединение

| С платы A | На плату B |
|---|---|
| GP4 (передаёт) | GP5 (принимает) |
| GP5 (принимает) | GP4 (передаёт) |
| GND | GND |

- **Линия работает на 15 Мбит/с,** 8N1, 3,3 В, с подтяжкой на принимающем выводе. Провода — короткие, около 20 см. Для длинных соберите обе платы на меньшую скорость:
  ```bash
  cmake -DLINK_BAUD=7500000 ...
  ```
  `LINK_TX_PIN` и `LINK_RX_PIN` переносят линию на другие выводы.
- **Не соединяйте выводы 3,3 В или 5 В двух плат.** Каждую питает её машина.

## Что видит каждая машина

Одно USB-устройство «MIND Core MIND Link», серийный номер которого — уникальный идентификатор платы. Для каждого класса есть драйвер в Linux, Windows 10 и новее, macOS и MIND Core (800-LNK-0006), так что ничего ставить не нужно.

| Интерфейс | Что | Имя в Linux |
|---|---|---|
| 0–1 | **serial**: порт CDC-ACM | `/dev/serial/by-id/usb-MIND_Core_MIND_Link_<серийный>-if00` |
| 2–3 | **data**: порт CDC-ACM | `…-if02` |
| 4–5 | **control**: порт CDC-ACM | `…-if04` |
| 6 | клавиатура, boot-протокол | — |
| 7 | мышь, boot-протокол | — |
| 8 | планшет: абсолютный указатель, 0–32767 по каждой оси | — |

- **Порты serial и data:**
  - байты, записанные в один, выходят из одноимённого порта другой платы;
  - скорость, заданная порту, роли не играет;
  - каждое направление управляется потоком из конца в конец: плата берёт у своей машины не больше, чем есть места у другой платы;
  - байты для порта, который никто не открыл, отбрасываются, как на последовательной линии.
- **Файлы:** `mindlink` работает через порт data, как через любой последовательный порт:
  ```bash
  # испытуемая машина:   mindlink /dev/serial/by-id/...-if02 serve ~/link
  # машина разработки:   mindlink /dev/serial/by-id/...-if02 put build.img
  ```

## Порт управления

Строки текста, каждая заканчивается LF. `mindlink <порт управления> board <строка>` посылает одну и печатает ответ.

Команды ввода исполняются на клавиатуре, мыши или планшете **другой** платы, то есть на другой машине. Ответ — `ok` или `err <причина>`.

| Строка | Что делает |
|---|---|
| `hello` | `MIND Link 1 <плата> <серийный> peer <серийный другой платы или none>` |
| `status` | состояние другой платы и счётчики: байты в каждую сторону, потерянные байты, испорченные кадры |
| `type <текст>` | набирает ASCII-текст в раскладке US, не больше 249 символов в строке |
| `key <сочетание>` | нажимает сочетание и отпускает: `key ctrl+alt+delete`, `key gui+r`, `key f2`, `key enter` |
| `move <dx> <dy> [<колесо>]` | сдвигает мышь |
| `wheel <n>` | крутит колесо |
| `click [left\|right\|middle]` | щелчок |
| `press <кнопка>`, `release <кнопка>` | держит или отпускает кнопку; сдвиги идут с ней, для перетаскивания |
| `abs <x> <y>` | ставит указатель планшета в x, y, от 0 до 32767 по ширине и высоте экрана |

**Имена клавиш:**
- буквы, цифры и знаки;
- `enter`, `esc`, `backspace`, `tab`, `space`, `delete`, `insert`, `home`, `end`, `pageup`, `pagedown`, `up`, `down`, `left`, `right`, `capslock`, `printscreen`, `scrolllock`, `pause`, `menu` и `f1`–`f12`;
- модификаторы `ctrl`, `shift`, `alt`, `gui` (`win`) и правые `rctrl`, `rshift`, `ralt` (`altgr`), `rgui`.

Клавиатура и мышь работают по boot-протоколу, поэтому действуют и в меню прошивки. Планшету нужна система с драйвером HID.

**Строки индикатора** (issues-human, раздел 8) тоже принимаются, без ответа. Машина с MIND Core может посылать их, чтобы показывать свою загрузку на светодиоде своей платы:
- `@STATE KERNEL`, `@STATE SERVICES <n>/<всего>`, `@STATE READY`, `@STATE REBOOT`, `@STATE OFF`;
- `@HEALTH OK|WARN|FAIL <причина>`;
- `@BEAT <мс>`.

## Светодиод

| Цвет | Значение |
|---|---|
| Тусклый синий | Питание есть; машина плату ещё не настроила |
| Тусклый голубой | Машина настроила, другая плата не отвечает |
| Тусклый зелёный | Обе платы отвечают; ярче, пока идут данные |
| Красный, мигает | Испорченный кадр, потерянный байт или переполнение за последнюю секунду |

Когда машина присылает `@STATE`, плата вместо этого показывает загрузку машины:
- жёлтый, ярче по мере запуска служб;
- зелёный при `READY`;
- оранжевый при `HEALTH WARN`, красный при `FAIL`;
- мигающий пурпурный, когда удары сердца пропали на 3 с;
- белые вспышки при `REBOOT` или `OFF`.

## Между платами

- **Кадры:** закодированы COBS и закончены нулевым байтом. Каждый несёт:
  - тип (hello, data, credit) и канал (serial, data, control);
  - смещение своего первого байта в потоке и до 256 байтов;
  - CRC-16/CCITT.
- **Кредиты:** плата посылает не больше 4 КиБ сверх того, что машина другой платы уже забрала. Кредиты несут абсолютные смещения, поэтому потерянный кредит восполняет следующий.
- **Испорченный кадр** отбрасывается и считается. Его байты потеряны, и приёмник пропускает их, а не ждёт. Протокол на порту data (`linkproto`) повторяет свой запрос; байты порта serial просто теряются, и светодиод это показывает.
- **Ядра:** ядро 1 обслуживает два автомата PIO линии. Ядро 0 обслуживает USB, кадры и интерфейсы HID.

## Ожидания, ещё не измеренные

- **Линия:** 15 Мбит/с несут около 1,4 МБ/с кадров в каждую сторону, больше, чем примерно 1 МБ/с у USB full speed.
- **`mindlink` через пару** передаст меньше, чем могут порты. Каждый запрос в 1 КиБ ждёт ответа через два перехода USB. Протокол с несколькими запросами в пути — следующий шаг.
- **0,9 МБ/с из критерия приёмки** измеряются на самом порту data.

## Тесты

`devices/rp2-link/tests/host_test.c`, их запускают `build.sh` и `scripts/host_tests.sh`:
- COBS и CRC;
- каждый испорченный байт кадра пойман;
- шум и слишком длинная серия;
- кредиты через перенос смещений;
- поток через линию, которая теряет 3 % кадров, и окно никогда не переполняется;
- каждая команда управления;
- таблица светодиода.

Это свидетельство только для логики, а не для платы (MC-12.1).

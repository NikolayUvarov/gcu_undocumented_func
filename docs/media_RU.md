# Снимки и видео MIND

Как делаются снимки и видео для страницы проекта (000-KRN-0093). English: [media.md](media.md).

Под каждым снимком сказано, где он снят: в машине QEMU или на названной настоящей машине (MC-12.1). Снимок показывает, что одна сборка сделала на одной машине, а не то, что сделает любая.

## 1. В QEMU: одни и те же сцены при каждом обновлении

`scripts/qemu_scenes.py` загружает текущую сборку x86 (`usb_root`) в машине тестовых наборов с экраном 1920 × 1080 и сохраняет постоянные сцены в PNG:

| Сцена | Что на ней |
| --- | --- |
| `boot` | оболочка после загрузки, со строками служб |
| `check` | таблица `check kernel` |
| `top` | `top`, пока работает `clock` |
| `wm` | `wm` с `fm`, `clock`, `top` и окном оболочки |
| `series` | окна `wm` сменяют друг друга, кадр каждые полсекунды; ещё и анимированные WebP и GIF |
| `tour` | анимация для страницы: загрузка, `check`, `hw`, `top`, `wm` и три его окна во весь экран, каждый кадр уходит в следующий через затемнение; WebP без потерь, ширина 1280 (экраны оболочки обрезаны с левого верхнего угла, экраны `wm` уменьшены). Играет свои сцены сама, поэтому запускается отдельно |

```bash
./02_build.sh
python3 scripts/qemu_scenes.py -o media-scenes            # все сцены, около 30 с
python3 scripts/qemu_scenes.py --scenes wm,series          # некоторые
python3 scripts/qemu_scenes.py --scenes tour -o media-scenes && cp media-scenes/tour.webp docs/media/   # анимация для страницы
```

Принимает те же `--qemu`, `--firmware` и `--cpus`, что и наборы, и `--size` для другого экрана. WebP и GIF делает ffmpeg.

## 2. На настоящей машине

Файлы в `data/` остаются на загрузочном диске, который читают Windows и macOS. Файлы на `ram:` пропадают при перезагрузке.

- **Снимок экрана оболочки:** `screenshot data/screen-001.bmp`. Снимается экран, который впереди; набранная в оболочке команда снимает экран оболочки: строки загрузки, таблицы `check` или `bench`.
- **Запись экрана:** `run record -r 5 -t 20 data/wm.avi &`, затем программа, которую надо показать, например `wm`. `record` всё время пишет тот экран, что впереди, какой бы он ни был, а композитор в это время показывает красную точку в углу. `-r` — кадров в секунду, `-t` — секунд.
- **Запись одного окна:** `record -w -t 10 data/window.avi` в строке запуска `wm` (Alt+R). Пишется только окно впереди, в размере его содержимого.
- **Снимок `wm`:** запишите несколько секунд, затем возьмите кадры через `media.py series` (ниже) и выберите один.

Снимок по клавише, без оболочки на экране, запрошен у трека инструментов ([requests-APP.md](../issues/requests-APP.md)).

На MacBook Pro экран 2880 × 1800: BMP занимает около 15 МБ. Запись растёт с тем, что меняется на экране: кадр, такой же, как предыдущий, байтов не занимает.

## 3. Преобразование: `scripts/media.py`

```bash
python3 scripts/media.py shots  screen-001.bmp              # screen-001.png и screen-001-1600.png для страницы
python3 scripts/media.py series wm.avi                      # wm/frame-NNNN.png (каждая отличная картинка), wm.webp, wm.gif
python3 scripts/media.py series a.bmp b.bmp c.bmp --fps 1   # ряд снимков, по секунде каждый
python3 scripts/media.py video  wm.avi                      # wm.mp4: H.264, yuv420p, не шире 1920, меньше 10 МБ
python3 scripts/media.py slideshow a.png b.png -o show      # show.webp: по 2,5 с, переход через затемнение, по кругу
```

- **Один Python** читает BMP и AVI и пишет PNG в полный размер. Масштаб, WebP, GIF и MP4 делает ffmpeg.
- **Размер каждого результата** печатается. `--width` задаёт наибольшую ширину; `video --limit-mb 100` — предел GitHub на платных планах.
- **Красная точка** остаётся в записанных кадрах: это знак записи, а не дефект.

`tests/media_test.py` проверяет чтение и запись PNG на маленьких файлах, которые делает сам, и три команды там, где есть ffmpeg.

## 4. Куда идут результаты

- **Снимки** для страницы — в `docs/media/` этого репозитория, каждый меньше 1 МБ (копия для страницы от `shots` или кадр от `series`), а анимация страницы — меньше 2 МБ (`docs/media/tour.webp`). Витрина копирует их вместе с `main`.
- **Видео** прикрепляются на GitHub (в задаче, выпуске или редакторе страницы), а не коммитятся: MP4 меньше 10 МБ.
- **Под каждым снимком:** машина (QEMU или модель настоящей машины), размер экрана и коммит сборки.

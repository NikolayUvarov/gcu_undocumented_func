## Platform

- x86-64, UEFI (OVMF in QEMU), 1–8 xAPIC CPUs, no SMT siblings in the tested configuration (`-smp N,cores=N,threads=1`).
- QEMU `pc` machine with IDE, optionally AHCI, xHCI with USB mass storage, AC97; physical machines boot from the USB image but are not part of the evidence.
- **No IOMMU is used.** Every device that can do DMA can read and write all physical memory.
- One node. Up to two VirtIO network cards (QEMU `virtio-net-pci`; one driver instance and one interface per card, issue 105) and an IPv4 stack (`netstack`, DHCP, ICMP, DNS, UDP, TCP) run in ring 3. Flows follow the policy broker (`netpolicy`, `netpolicy.txt` on the boot disk, issue 102): an application reaches only the destinations, term and volume its grant names; the shell's client has the operator's badge and reaches any destination. TLS 1.3 client sessions (`tls`, issue 103) run over a flow the client lends, with server certificates verified against `tlsroots.pem` on the boot disk; random numbers come from RDRAND only (no RDRAND: no TLS and no device key). Network confidentiality and integrity are claimed only for those sessions, not for the stack's other traffic. Network performance and the offload decision: [network.md](network.md).

## Conformance

Status: **met** (implemented and tested within this profile; each met row names its evidence, details in [evidence.md](evidence.md)), **partial**, **not met**, **not claimed** (outside this profile). Requirement IDs are `MC-<article>.<clause>` of Constitution v1.6.

| Requirement | Status | Notes |
|---|---|---|
| MC-1.1, 1.3 minimal kernel, drivers outside | partial | Drivers, file system, loader, audio, TTS, command shell and service policy run in ring 3. The kernel still parses ELF images for `SPAWN` and enumerates PCI (discovery, not policy). |
| MC-1.4 policy separate from mechanism | partial | `init` decides what each service gets; the kernel validates every resource it mints (legacy port allowlist, enumerated BARs, IRQ lines) regardless of `init`'s correctness. Evidence: `services` suite (services start with exactly init's grants). The kernel's refusal of out-of-profile `PLATFORM_CAP` arguments has no test (only `init` holds the privilege). |
| MC-1.5 DMA boundary | **not met — declared** | No IOMMU and no interrupt remapping (a device that can write memory can also send any MSI): every MSI-X entry is programmed by the kernel and drivers are not granted the BAR with their MSI-X table, but this is not a boundary against the device; `ahci`, `usb_storage`, `audio_gw`, `virtio_net` and their devices are in the TCB of every memory-isolation guarantee ([tcb.md](tcb.md)). Isolation from them is not claimed. |
| MC-1.7 accounted creation | partial | Tasks and endpoints are charged to an owner's quota delegated at spawn ([kernel-objects.md](kernel-objects.md)). Task memory from the frame pool is charged to a memory quota: private memory to the task and every payer above it (issue 150), a task's image, stack and screen to its spawner and every payer above it (issue 168); shared mappings have per-task limits. Evidence: `memory` suite (loader's account grows by exactly a started program's image, stack, screen and private memory and returns at exit). Not charged to owners: page tables and kernel structures (the 64 MiB arena), DMA regions (a global limit). A spawn refused for its spawner's memory quota has no test (loader holds all of init's quota, so the frame pool runs out first). |
| MC-1.8 reuse without residue | partial | All task memory is zeroed on allocation; freed memory is not reused while any mapping or capability refers to it. Devices are not reset on driver restart. |
| MC-2.1 isolated state | met | Private page tables; sharing only through memory capabilities. Evidence: `isolation` suite cases r, w, t, n; host test `same_virtual_address_maps_private_frames_in_distinct_cr3s`. |
| MC-2.3 typed, versioned interfaces | partial | MIND IDL v0.2 ([docs/idl](../idl/README.md)): typed, versioned WIT-subset interfaces with bounded records, strings and lists, capability kinds, generated bindings, schema checks on a private copy in the receiver. Its minor extension adds enums, `bytes<N>` and capability results. The services use it (`rtc`, `block`, `vfs`, `loader`, `init`, `audio`, `tts`, `sysinfo`, `log`); the compositor's messages and the kernel's notices are numeric conventions in `common/abi.rs`. Ordering and session contracts are not described. |
| MC-2.5 bounded queues, back-pressure | met | IPC is a rendezvous (no kernel message queue); at most `ENDPOINT_QUEUE` (4) senders wait per endpoint, a further send fails with `ERR_BUSY`. Every send, call and receive may carry a timeout; expiry withdraws the operation without a trace, and a later reply to that call fails with `ERR_PEER`. Timeouts have 10 ms granularity. Evidence: `isolation` cases `k` (timeouts), `q` (queue bound with five senders), `j` (late reply). |
| MC-2.6 transfer modes | partial | COPY: two data words per message. MOVE: a detached memory object (`MEM_DETACH`) has one writable owner and is transferred only with `CAP_TRANSFER_MOVE`, and not while its sender maps it (issue 167: the model [`CapRevokeMove`](../assurance/README.md) found that the sender's mapping could stay a second writer). SHARE_RO: a read-only capability the kernel reports as sealed (no writer, no DMA). LEASE: a copy ended by `CAP_REVOKE`, which unmaps it with a completion point. Every service transfer uses one of these modes or a `SHARE_RW` adapter listed under [Memory transfers](#memory-transfers-appendix-b2). Without an IOMMU a DMA-capable device is not bound by any of them. |
| MC-3.1, 3.2 explicit, unforgeable capabilities | met (kernel-allocated slots) | Capabilities live in a kernel table and are named by 64-bit handles `slot \| generation << 24` (24 bits of slot, 32 of generation; issue 172). A slot the kernel hands out gets a new generation when freed, so a stale handle is rejected; a generation wraps after 4 294 967 295 reuses of one slot. Fixed slots 1–22 are named by their owner and overwritten only by the owner's own receive. Evidence: `isolation` case `k` (stale handle after slot reuse, mint and revoke; 300 capabilities in slots beyond 255, revoked together, a reused slot's old handle refused). |
| MC-3.3 no implicit authority for new domains | met | A new task gets exactly the spawner's grant list (`SPAWN`). Endpoints have no global names; a service is reachable only through a capability `init` derived for the client. Evidence: `isolation` case `k` (an application holds no privilege: input, ports, spawn, platform, control refused). |
| MC-3.4–3.6 copy/move/attenuate/revoke | partial | Copy and move are distinct; `CAP_MINT` attenuates endpoint rights and port/memory ranges and can badge an endpoint child once (the server tells clients' rights apart by the badge: block writes need the write badge, Appendix B.6); `CAP_REVOKE` removes all descendants (including one in a blocked send) before it returns. Mappings made from a revoked capability are removed before `CAP_REVOKE` returns. TLA+ models of the capability tree and of the completion point on several CPUs are checked by TLC within stated bounds ([docs/assurance](../assurance/README.md), issue 167): a model check, not a proof of the code (MC-12.2). `vfs_server` handles follow the same rule: one opened from another is never wider. |
| MC-3.7 no identity bypass | met | Every privileged system call checks a capability; no PID or name grants rights. A program's `.mind_request` section only asks: the shell decides what to lend in a launch session (`idl/loader.wit`), and the loader copies only what it was given. Evidence: `isolation` case `k` (privileged calls refused without the capability). |
| MC-3.12 end of initial distribution | met | Bootstrap authority is only `init` ([bootstrap.md](bootstrap.md)). Before `[INIT] READY` it gives up the platform privilege; it keeps the capabilities it handed to each service and a restart privilege that can only spawn boot images. The privileges it hands out (input, display, spawn, process control, observe) it keeps in escrow: it can pass them to a service it starts, which gets the privilege, but cannot use them itself; it holds no process control and ends tasks as their ancestor (issue 170). The device capabilities it keeps (ports, MMIO, IRQ lines, DMA regions) stay usable by it: it stops devices through them (`DEVICE_STATE`). Evidence: `services` suite (`PLATFORM PRIVILEGE DROPPED`, restarts afterwards; init's capabilities hold no usable input, display, platform, control or observe privilege; `sysmon` and `loader` restarted from escrow work; applications and services stopped through init). |
| Article 4 storage | not claimed | FAT volumes are external media written in place, without a journal ([threat-model.md](threat-model.md)); there is no content-addressed store. The identifier format the store will use (CIDv1, `raw` or `dag-cbor` content, SHA-256: version and algorithm named, unknown formats refused, MC-4.2, 4.13) is implemented in `libmind` and tested on the host ([docs/storage](../storage/README.md)). The block store `blockstore` (append-only, every read checked against its CID, put and get rights by badge, names published by compare-and-swap only for complete roots) and the format of objects larger than a block (a Merkle-DAG of chunks and DAG-CBOR nodes, `mind::dag`) are built and tested on the host only: `init` does not start the store yet, so nothing is stored by CID on this platform. |
| MC-5.1–5.5 budgets | partial | Scheduling contexts (C7): a CPU budget per period, enforced at the 10 ms tick, set by the lifecycle owner or process control (`SCHED_SET`); two bands — `init` and services run before applications, so the supervisor's reserve survives application overload. Evidence: `busy` suite (a 20 ms/100 ms budget keeps a busy loop near 20 %), `smp` suite (`init` restarts a service while every CPU is saturated). Memory: quotas per owner are limits, not reservations; the system band has a recovery reserve of the frame pool (issue 169). Not provided: deadlines, admission control, budgets below the tick, memory reservations per owner. |
| MC-5.6 explicit clocks | met (measurement) | Monotonic `CLOCK` with stated resolution, calendar time as a separate service; deadlines still have 10 ms granularity. See [clocks.md](clocks.md). Evidence: `services` suite (`clock` command). |
| MC-6.1, 6.2 fault containment | met (ring 3) | A user exception terminates only that task, is recorded (`faults`) and its resources are reclaimed; kernel exceptions halt the system. Evidence: `isolation` suite (each fault case leaves the other tasks running; heap baseline restored). |
| MC-6.4–6.9 supervision | partial | `init` is the lifecycle owner of every service: the kernel sends it exit notices (`TASK_WATCH`), it restarts a failed service at most 3 times in 60 s and then quarantines it until an explicit `RUN`. Sends queued for a dead server fail with `ERR_PEER` instead of reaching the next instance; clients tell instances apart by the server PID in replies. Without `init` the system halts. Evidence: `services` suite (restart, budget, quarantine, halt), `isolation` case `f` (queued send fenced). Before a driver restarts, its device is stopped (`DEVICE_STATE`) and its DMA region cleared (MC-6.3, `ahci` and `net` suites). The block client re-attaches to a new driver instance and repeats only idempotent reads (MC-6.6). The supervisor does not depend on memory applications can exhaust (MC-6.5, issue 169): `init` keeps 32 MiB of the frame pool for the system band (`MEMORY_RESERVE`), and application-band allocations stop above it. Evidence: `memory` suite (applications that take all they can leave the reserve; `rtc` killed meanwhile restarts and serves). The window broker, a service, allocates application windows' surfaces and can draw on the reserve within its own quota; the reserve is free memory, not a contiguous block. Not done: idempotency rules for other protocols, lifecycle owners of applications beyond loader's accounting. |
| Articles 7, 8 | not claimed | Single node; no safety plane. |
| Article 9 boot and update | not met — declared | Boot images are not signed or measured; the bootloader loads whatever is on the boot volume. |
| MC-10.2 observability under authority | met | Task logs, console output, task list, faults and CPU data are readable only with the process-control privilege (the shell). Evidence: `isolation` case `k` (`TASK_KILL`, `FOCUS`, `HALT`, `REBOOT` refused to an application). Statistics (`STAT`, task list, CPU data, kernel heap, faults) need the observe privilege or process control; kill, focus, logs and console output need process control. `STAT` exports no task memory contents, no physical address of task memory and nothing usable as authority (endpoint indices are labels). The `sysmon` service (`idl/sysinfo.wit`) holds the observe privilege and answers only programs a launcher granted its endpoint (`SLOT_SYSINFO`). |
| MC-10.5 side channels | not claimed | No mitigation is claimed. |
| MC-11.1 explicit ABI | partial | The ABI is a `repr(C)` mailbox and constants in `common/abi.rs`, with a version (`ABI_VERSION` 2 since issue 172): the kernel writes it into every task's `BootInfo`, and a program built with `libmind` for another version stops with `ABI MISMATCH` (exit 126). Evidence: `boot` suite (a kernel built with `abi-test` reports another version: init stops and the system halts with that reason). Not done: no compatibility for older programs (a mismatch only refuses), no version for service interfaces beyond their IDL versions, programs that do not use `libmind` are not checked. |
| MC-11.3, 11.11 external formats in adapters | partial | FAT and USB/SCSI parsing run in ring 3 services with only their device capabilities; network frames, IP, TCP, UDP, DHCP and DNS are parsed in `netstack`, which holds only a client of the card driver (B.6); TLS records and X.509 certificates are parsed in `tls`, which holds neither network access of its own nor the private key; ELF parsing of applications runs in the kernel. |
| MC-11.6 Babel access scope | partial | The network policy broker grants each program that asks for the network (`REQUEST_NETWORK`) a stack client with its own badge; the stack refuses (`denied`) every destination, protocol and port the grant does not name, ends it after its term or volume and when the program exits, and closes its flows when the grant is revoked (`netrevoke`); every grant, refusal and revocation is logged. Evidence: `net` suite. Not done: names in the policy (addresses only), policy changes by an authorized editor (the file is on the read-only boot volume), flows from the shell's operator client are unrestricted. |
| MC-11.9 key material apart from key operations | partial | The device key (Ed25519, made from RDRAND at boot) exists only in the memory of `keystore`; no call returns it. The TLS service holds a client with the signer's badge and may ask only for a signature of the form the purpose names (a TLS 1.3 client CertificateVerify), at most 4096 per boot; every signature and refusal is logged. Other programs can only read the certificate (through `tls`). Evidence: `tls` suite (the device certificate accepted by a server that trusts exactly it; only `tls` holds a client of `keystore`; without RDRAND no key). Not done: a signature is not bound to a session the key service can check (a compromised `tls` can get any transcript hash of that form signed, within the budget), budgets per client, a key that survives a reboot; sessions of different clients share the `tls` process (each is bound to its owner's PID, but their plaintext is not separated by process). |

## Memory transfers (Appendix B.2)

Every memory capability a service hands to another task, and its mode (MC-2.6). `MEM_SHARE` makes a capability for a block of the caller's own heap; the modes below say what the receiver gets and when its access ends.

| Transfer | Mode | Receiver's access | Ends |
|---|---|---|---|
| MIND IDL buffer calls (`vfs`, `tts`, `loader`, `init`: `wire::call_buffer`) | LEASE, read-write | the server copies the request into private memory before decoding and writes the reply | `CAP_REVOKE` by the client before it reads the reply |
| `audio.play` (`mind::audio`) | LEASE, read-only | `audio_gw` copies the PCM into its DMA ring | `CAP_REVOKE` after the reply |
| `audio.record-read` | LEASE, read-write | `audio_gw` writes captured samples | `CAP_REVOKE` before the client reads them |
| `video.read` (`camera`) | LEASE, read-write | `video_gw` writes one frame | `CAP_REVOKE` before the client reads it |
| `block.attach` (`vfs_server` → `ata`, `ahci`, `usb_storage`) | **SHARE_RW** adapter | the driver writes sector data during `read` calls; `vfs_server` copies it into its private cache right after each reply and parses only that copy (the private-copy condition of MC-2.6) | `CAP_REVOKE` on re-attach to a restarted driver and when the device is closed |
| `usb.attach` (`usb_storage`, `usb_hid` → `usb_host`, issue 164) | **SHARE_RW** adapter | `usb_host` writes interface descriptions, control replies, bulk data and interrupt reports into the class driver's buffer during calls, and reads the data the driver puts there to send; the class driver copies data out after each reply. One buffer per badge; a new one replaces it and frees the old client's interfaces | `CAP_REVOKE` by the class driver before it attaches again, and when it ends |
| Task screens → `compositor` (kernel, `COMPOSITOR_PULL`) | **SHARE_RW** adapter, read-only for the compositor | the owner keeps drawing while the compositor copies the pixels into its shadow buffer and the framebuffer; pixels have no structure to validate, so a torn frame is the only effect (display fences: track G) | the next focus change replaces the capability |
| `net.attach` (`netstack` → `virtio_net`, the frame ring, issue 107) | **SHARE_RW** adapter | both sides write their own counters and slots: the stack queues frames to send, the driver queues received frames; each side copies a frame out of its slot before using it, and checks every counter and length it reads (a slot with an impossible length is skipped; a counter more than the ring's size ahead is ignored) | `CAP_REVOKE` by the stack when it lends a new ring; the driver drops the ring when the stack's task ends or stops kicking for a second |
| `window.surface` (`windows` → a program and its window manager, issue 157) | **SHARE_RW** adapter, memory of the broker | the program draws and queues nothing but its content and title; the manager copies the content out (after `mind::window::Surface::check`: kind and size within the memory) and writes only the requested size, the state and input events; neither can revoke the other's lease, since both come from separate children of the broker's capability | the window's end (`CAP_REVOKE` of the whole surface); the manager's lease also when it detaches or ends |
| `ping` → `pong` (demo) | LEASE, read-only | `pong` reads the text | `CAP_REVOKE` after the reply |
| `SPAWN` image (`loader`) | not transferred | the kernel copies the image during the call | the capability is dropped after `SPAWN` |
| Driver DMA regions (`init` → drivers) | owned by the driver | `PLATFORM_CAP` DMA region, cleared by `init` before a restart | the driver's exit |

`SHARE_RW` is used only by the four adapters above. Not claimed: the end of a lease bounds the receiver's access through its mappings, not what it copied while it held them.

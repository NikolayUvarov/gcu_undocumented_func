# msh — язык сценариев оболочки

`msh` (задача 094) — собственный небольшой язык оболочки: для последовательностей запуска, тестов, повторяющихся задач
и рецептов. Это не оболочка POSIX: нет головоломок с кавычками, глобального окружения и фоновых полномочий. Команды
возвращают **результаты**, как в Marain (RFC 001 §7.5), а сценарий объявляет, что ему нужно.

Интерпретатор — `mind::script` (libmind, с возможностью `alloc`): разбор в синтаксическое дерево, затем вычисление
обходом дерева с бюджетом шагов. Оболочка — его хозяин: команды, типизированные ответы системы, вывод.

[English version](msh.md)

## Запуск

| Как | Что |
|---|---|
| `msh data/sum.msh a b` | выполняет файл сценария; `args` — это `["a", "b"]` |
| `data/sum.msh a b` | то же: имя, оканчивающееся на `.msh`, — сценарий |
| `msh -c "let x = 1; print(x)"` | одна строка, с переменными приглашения |
| `msh --check data/sum.msh` | разбирает и называет функции, которых нет |
| `let`, `if`, `for`, `while`, `fn`, `try`, `name = …`, `name(…)`, набранные в приглашении | оператор; переменные и функции консоли сохраняются |

Сценарий останавливается на первой необработанной ошибке: `SCRIPT FAILED: причина (LINE n)`. Esc или Ctrl+C на любой
клавиатуре, а также Ctrl+Z на последовательной линии останавливают его: `SCRIPT STOPPED: stopped`. Так же
останавливается сценарий, исчерпавший бюджет шагов (десять миллионов).

## Сценарий

```
#!msh
requires: files
# Файлы на ram:, их размеры суммируются в ram:summary.txt; отсутствующий файл обрабатывается.
let total = 0
let names = []
for f in files("ram:")? {
    if f.dir { continue }
    total = total + f.size
    names = push(names, f.name)
}
write ram:summary.txt "{len(names)} files, {total} bytes: {join(names, " ")}"
cat ram:missing.txt or { print("handled: {error}") }
print("done: {total}")
```

## Строки

- Один оператор на строке или несколько через `;`. `#` начинает комментарий.
- Строка, начинающаяся с имени, — **команда**, если имя не ключевое слово и за ним нет `(` (вызов) или `=`
  (присваивание).
- **Слова команды.** Слова разделяются пробелами. `"слово в кавычках"` сохраняет пробелы. `{выражение}` внутри слова
  или слова в кавычках подставляет значение. `\` берёт следующий символ как есть.
- **Конец команды.** Её заканчивают строка, `;` или `}`. Последнее слово `or` с обработчиком обрабатывает её неудачу.
- **Команды.** Команда — собственная команда оболочки (`ls`, `write`, `ping`, …) или программа. Она ждёт завершения
  консольной программы. Возвращает `ok(nil)` или `err(причина)`, если напечатала строку `ERROR:` или её программа
  завершилась плохо: код завершения не 0 (`grep exited with 1`: совпадений нет), снятие, сбой (задача 166).
- **Операторы:**

| Оператор | |
|---|---|
| `let name = expr` | переменная в текущем блоке |
| `name = expr` | меняет переменную, созданную `let` |
| `if cond { … } else if cond { … } else { … }` | `cond` должно быть `true` или `false` |
| `while cond { … }`, `for item in list { … }` | `break`, `continue` |
| `fn name(a, b) { … return value }` | функция видит свои параметры и внешние переменные сценария |
| `try { … } catch e { … }` | `e` — причина неудачи |

## Значения

| Значение | Запись |
|---|---|
| ничего | `nil` |
| логические | `true`, `false` |
| целые | `42` (64 бита, переполнение — ошибка) |
| строки | `"текст {expr} \n \t \" \\ \{"` |
| списки | `[1, "two", [3]]`, индекс `list[0]`, `list[-1]` |
| записи | `{name: "x", size: 3}`, поле `r.name`, `r["name"]` |
| результаты | `ok(значение)`, `err(причина)` |

Операции, от низшего приоритета:
- `or` (обработчик);
- `||`, `&&` (только логические);
- `==`, `!=`, `<`, `<=`, `>`, `>=` (целые или строки);
- `+`, `-` (`+` также соединяет строки и списки);
- `*`, `/`, `%`;
- `!`, `-`;
- постфиксы `.поле`, `[индекс]`, `?`.

## Результаты

Каждая команда и каждая функция, которая может не удаться, возвращает `ok(значение)` или `err(причина)`. **После
ошибки ничего не продолжается молча**:
- Оператор, значение которого `err(r)`, проваливает сценарий на месте: строка команды, вызов, `err("x")`.
- `expr?` — значение внутри `ok(v)`; на `err(r)` — неудача.
- `expr or { … }` или `expr or другое` обрабатывает неудачу или `err(r)`: обработчик выполняется с `error`, равным `r`,
  и его последнее значение становится значением.
- `try { … } catch e { … }` обрабатывает любую неудачу в блоке.
- `fail(причина)` — неудача сразу.
- Результат, сохранённый в переменной (`let r = capture("ps")`), — это значение. Использовать его как строку или число
  нельзя: будет неудача с напоминанием взять значение через `?` или `or`; проверки — `is_ok(r)` и `is_err(r)`.

## Функции

- **Встроенные:** `print(…)`, `len`, `str`, `int` (`err`, если не число), `type`, `lines`, `words`,
  `split(текст, разделитель)`, `join(список, разделитель)`, `trim`, `upper`, `lower`, `replace(текст, что, чем)`,
  `contains` (строка, список или поле записи), `starts_with`, `ends_with`, `match(текст, образец)` (образцы `grep`:
  `.` `*` `[a-z]` `^` `$`), `push(список, элемент)` (новый список), `range(a, b)`, `keys(запись)`, `ok`, `err`, `fail`,
  `is_ok`, `is_err`, `unwrap`.
- **От оболочки:**

| Функция | Возвращает |
|---|---|
| `capture("строка команды")` | `ok(текст)`: напечатанное командой, не на экран; или `err(причина)` |
| `ps()` | `ok([{pid, name, state, cpu, service, focus, console}, …])` |
| `services()` | `ok([имя, …])`: работающие службы |
| `files(каталог)` | `ok([{name, size, dir}, …])` |
| `glob("ram:*.txt")` | `ok([путь, …])`: имена в каталоге, подходящие под маску (`*`, `?`, без учёта регистра) |
| `log(текст)` | строка в системном журнале (нужно `log`) |
| `sleep(мс)` | ждёт (Esc или Ctrl+Z прерывают) |
| `now()` | время работы в миллисекундах |

## Полномочия

- Сценарий выполняется с полномочиями сеанса оболочки, который его запустил, **но не больше, чем объявил**.
  Объявление — его первая строка после `#!msh` и комментариев: `requires: files network`, словами `mind::request!`:
  - `files`: `write`, `mkdir`, `rm`, `mv`, `sync`, `screenshot`;
  - `network`: `ping`, `nslookup`, `fetch`, `https`, `net`, `netrevoke`, `ip`, `tls`;
  - `log`: `logger`, `log()`;
  - `lifecycle`: `kill`, `budget`, `stop`, `reboot`.

  Без своего слова команда не выполняется: `ping needs requires: network in the script`.
- **Программы, запущенные сценарием,** получают из того, что просят, только объявленное сценарием (`sysinfo`, `file`,
  `files`, `log`, `lifecycle`, `network`, `authority`, `display`, `window-manager`, `gpio`, `camera`, `blockstore`, `firmware`);
  без остального они работают так. Программа, которая просит `camera` или `firmware`, получает их, только если
  пользователь ответит «да» на вопрос оболочки.
- **Сценарий не с загрузочного диска** (`ram:`, USB-диск) один раз спрашивает перед запуском:
  `SCRIPT ram:w.msh REQUIRES files. ALLOW? (Y/N)`.
- **Набранное пользователем** в приглашении (и `msh -c`) имеет полномочия сеанса.

## Пока нет

- **Программы переднего плана:** сценарий ждёт, пока такая программа завершится или уйдёт с переднего плана. Клавиши с последовательной линии во время ожидания до неё не доходят.

# 700-EFF-0004 — `mind::json`: a bounded JSON reader and writer

**Type:** library (`libmind`) · **Owner:** `EFF` track (open) · **Priority:** P1 · **Status:** open · **Blocked by:** — · **Main task:** [700](700-effector-agent.md) · **Constitution:** MC-11.5, MC-11.11, MC-2.5

## Problem

The Effector server speaks JSON, and no Rust program in MIND Core can read or write it. `serde` is not among the third-party crates, and a general-purpose parser with recursion would be an untrusted-input parser without bounds (MC-11.5).

Under the authority map ([docs/network/airlock.md](../docs/network/airlock.md)), JSON from the server is parsed in the `parse` service, not in the agent ([requests-NET.md](requests-NET.md), "JSON in the parser service"). This library is what that service would run. The agent itself only writes JSON.

## Plan

- **`libmind/src/json.rs` behind the `alloc` feature, `no_std`.**
- **A pull reader** that yields tokens with explicit limits:
  - nesting depth;
  - string length;
  - number of members;
  - total input.
- **Strict RFC 8259:**
  - UTF-8 input;
  - escapes, including `\u` surrogate pairs;
  - numbers as integers within `i64`/`u64` (decimals refused when the caller asks for an integer).
- **A small typed helper** to read the fields an object is expected to have and skip the rest, since the protocol says to ignore unknown fields.
- **A writer** that escapes strings and never produces invalid UTF-8.
- **Host tests** (`tests/json_host.rs`):
  - the JSONTestSuite cases;
  - deep nesting refused;
  - long strings refused;
  - duplicate keys handled as the contract says.
- **A fuzz target for 500's harness.** It is an `ASR` task, written when this lands.

## Acceptance criteria

- The host tests pass in `scripts/ci_local.sh`.
- Every limit has a test that hits it.
- The library allocates only within the limits given by the caller.
